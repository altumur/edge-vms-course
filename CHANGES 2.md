# Конфигуратор: что изменилось

Прототип: `index.html` + `assets/i18n-en.js`, без сборки. Исходный вариант лежит рядом: `index.before-search-ux.html` (4971 стр. → 6352 стр., 523 → 707 функций).

## Навигация

- Лента разделов слева: Оборудование, Автоматизация, Доступ, Опции, Журнал (Журнал — внизу, он для просмотра, а не настройки).
- Дерево одно, две независимые оси: **срез** (что показываем) и **группировка** (по папкам / по серверам). Переключатель группировки виден только там, где выбор реальный: у ACFA всегда папки, у Служб и Серверов — серверы.
- Срез «Серверы» показывает состав сервера: архивы, GPU, службы, нераспределённые серверы. Архив там не раскрывается — камеры смотрят в срезе «Камеры → по серверам».
- Группировка запоминается для каждого среза отдельно.
- Ссылки на объект: `#node=…&slice=…&group=…&tab=…`. Старые ссылки (`app=dev|srvs&view=…`) продолжают работать.
- Новый срез добавляется строкой в пяти константах рядом (`SLICE_RU`, `SLICE_SW_RU`, `SLICE_IC`, `SLICE_GROUPS`, `TYPE_FILTERS`).

## Поиск и переход

- Один движок везде: дерево, списки, таблицы, строка в шапке. Регистр и ё/е не важны, слова в любом порядке и из разных полей («вход главный» → «Главный вход»), неправильная раскладка тоже («gfhrjdrf» → «Парковка»). Совпадения подсвечиваются; если нашлось по скрытому полю (производитель, модель, ID) — поле показывается тегом.
- Строка в шапке — единая точка навигации. Индекс собирается из источников: разделы, срезы, страницы опций и **отдельные настройки**, роли и учётные записи, правила, категории журнала, закладки выбранного объекта, объекты дерева. Новая цель добавляется одним `registerJumpSource(...)`.
- Найденная настройка подсвечивается на открывшейся странице.
- При простом клике в поле сразу показываются недавние цели и разделы — переход в один клик.
- Клавиши: `Ctrl+K` — в поле, `↑↓` + `Enter` — выбор, `Esc` — сначала очистить, потом закрыть; в дереве `/` — к поиску по дереву, стрелки — ходить, `→ ←` — раскрыть/свернуть, `F` — в избранное.
- `Esc` закрывает ровно один слой сверху: сначала выпадающее меню внутри диалога, потом сам диалог, потом контекстное меню, меню пользователя, фильтры дерева, список поиска, множественное выделение. Работает и когда курсор стоит в поле ввода. Диалог мастера закрывается ещё и кликом по затемнению — как окно подтверждения.
- Найденный контейнер (папка, сервер, архив, домен) раскрывается со всем содержимым. Роль находится по логину пользователя. Из Журнала убрано поле поиска, которое ничего не фильтровало.
- Клик выбирает строку сразу (убрана задержка 250 мс), повторный клик по той же строке раскрывает её.

## Избранное

- В избранное добавляется любой объект дерева: звезда в строке (видна при наведении), пункт контекстного меню, кнопка в карточке объекта, клавиша `F`. При множественном выделении — «В избранное (N)».
- Группа «★ Избранное (N)» закреплена первой строкой дерева, одинакова во всех срезах и группировках, сворачивается, длинный список прячется под «ещё N». Поиск и фильтры дерева на неё не действуют — это адреса, а не выборка.
- Ярлык хранит не id, а полный адрес: объект, срез, группировку, папку вхождения и закладку. Один клик возвращает ровно туда, откуда ушли; строка подписана срезом, в который ведёт.
- Избранное — ещё один источник целей быстрого перехода: при пустом запросе идёт первым, в выдаче помечено ★ и не двоится со строкой из дерева.
- Удалённый объект не исчезает молча: ярлык остаётся зачёркнутым с пометкой «удалён» и убирается одним кликом.
- Хранится в `localStorage` (`cfg.favs.v1`), всё в `try/catch`: испорченные данные просто игнорируются.

## Устройства: закладка «Все устройства сети»

- Отдельной кнопки «Добавить устройство» больше нет — ни в дереве, ни в карточке, ни в контекстном меню, ни «＋» над таблицами. Устройства заводятся и привязываются на закладке, одинаковой у архива и у папки.
- В таблице одновременно и то, что уже в системе, и то, что нашёл поиск по сети. Найденное не двоится с заведённым: строка из сети показывается, только если в системе нет устройства с таким IP (и MAC).
- Колонка «Привязка» отвечает на главный вопрос сразу: «Пишется сюда» / «В этой папке», «Во вложенной: …», «Без папки» / «Без записи», где именно лежит чужое, «Нет в системе». Те же значения — чипами с количеством: Все · Здесь · Свободные · В другом месте · Нет в системе.
- Смысл привязки зависит от того, откуда пришли: у папки это расположение (`Убрать` / `В папку`), у сервера — запись в архив (`Отвязать` / `Писать сюда`, архив выбирается в шапке таблицы). Одно действие — одна кнопка в строке, пачкой — галочками.
- Невозможное не прячется, а объясняется: кнопка гаснет с подсказкой «Устройство в другом домене», «Запись в архив ведут только камеры», «У сервера нет архива», «Производитель не определён», «Объект лежит во вложенной папке».
- Поиск по имени, IP, MAC, производителю и модели — тот же движок, что везде; сортировка по любой колонке, «Показано: N из M», сброс фильтра. Поиск по сети идёт прогрессивно, строки появляются по мере находок, «Обновить» перезапускает.
- Ручной ввод и импорт из файла остались — кнопками под таблицей; в мастере у них больше нет шага «Поиск», он переехал сюда.
- Узкая карточка не ломает таблицу: производитель и модель уходят второй строкой под именем (container query), горизонтальной прокрутки нет.

## Фильтры

- Фильтры по типу и статусу работают одинаково во всех срезах и группировках (раньше в дереве серверов их не было вовсе, и один запрос давал разные результаты в разных разделах).
- Фильтр сам раскрывает ветки с результатами; ветки без содержимого скрываются.
- «Найдено: N» считает ровно то, что показано; объект из нескольких папок считается один раз.
- У объекта ровно один статус: Работает / Нет сигнала / Выключено / Лицензия превышена (прежнее «Включено» включало в себя объекты без сигнала). Статусы объединяются через ИЛИ.
- Из типов убран «Сервер» (в срезах устройств серверов нет), типы без объектов скрыты, на чипах — количество.
- Скрытый фильтром объект не подменяется молча: инспектор говорит об этом и даёт «Сбросить фильтры»; переход из поиска сбрасывает фильтры с уведомлением.

## Домены и серверы

- **Создание:** строка «＋ Домен» внизу дерева, пункт в контекстном меню и в карточке домена. Пустое или занятое имя не принимается.
- **Изменение:** имя и лицензия реально сохраняются («Сохранить» / «Отменить»), дубли подсвечиваются при вводе и при переименовании в дереве. В карточке — счётчики и блок «Действия».
- **Удаление:** диалог показывает содержимое и спрашивает, куда его перенести. Ничего не теряется: серверы становятся нераспределёнными в выбранном домене, устройства, папки и сетевые архивы переезжают туда же. Единственный домен удалить нельзя.
- **Пачкой из найденных в сети:** галочки у строк, «Выбрать все», «Добавить выбранные (N)», «Добавить все (N)», в контекстном меню — «Добавить все в домен (N)».
- **Пачкой по IP:** список адресов, диапазоны (`10.30.0.20-40`, `10.30.0.20-10.30.1.10`), подсети (`10.30.1.0/24`), свой порт (`10.30.0.5:20112`); разделители — перевод строки, запятая, пробел; до 1024 адресов за раз, `Ctrl+Enter` — поиск. Результат со статусами: Найден / Уже в домене «…» / Не отвечает / Не распознано.
- Контекстное меню появилось там, где его не было (домены, серверы, список нераспределённых).

## Заглушки (важно для дальнейшей работы)

- Опроса сети нет: `probeServer()` имитирует ответ — известные серверы определяются правильно, часть новых адресов намеренно «не отвечает». В рабочей версии заменить на реальный запрос.
- Поиск устройств в сети тоже имитация: 9 «найденных» адресов из `DEVICE_DISCOVERY_SEED` выдаются по таймеру. Заменить нужно только источник строк — вся таблица «Все устройства сети» строится из модели плюс этот список.
- Метрики сервера (ЦПУ, ОЗУ, Сеть) берутся из демо-данных, у сервера без связи — прочерки.
- Сохранение — только в памяти страницы.
