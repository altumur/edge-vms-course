# Урок 2 — Хранилище конфигурации

**Модуль:** М10A — Платформа (ServerVMS, часть первая)
**Вы напишете:** `w2cplatform/variables.py` — хранилище с теми же обещаниями, что даёт Nomad Variables, но на файлах: `ModifyIndex`, запись со сравнением версии, атомарность через переименование. И два теста, которые эти обещания ловят: перезапуск с устаревшим CAS и четыре потока, гонящиеся за один ключ.
**Время:** ~90 минут.

## Зачем этот урок

В М9 конфигурация лежала в Postgres, и все свойства, которые нам нужны, давал он: атомарность, версии строк, «кто первый». В М10 Postgres нет — он ушёл вместе с рекордером, потому что база данных на каждой коробке оказалась слишком дорогой вещью для того, чтобы хранить полсотни строк про камеры. Вместо неё будет **хранилище ключ-значение с проверкой версии**, и в М11 им станут Nomad Variables, которые в кластере всё равно есть.

Отсюда правило, которое определяет этот файл: **мы не изобретаем семантику, мы копируем обещанную.** Nomad Variables обещают ровно два свойства. Первое: у каждой переменной есть `ModifyIndex`, назначенный raft, и он растёт. Второе: `PUT` с `cas=<индекс>` проходит, только если индекс всё ещё тот; иначе — конфликт. Всё остальное в системе — эпохи, слоты, аренда, размещение, идемпотентность — построено на этих двух предложениях, и если наша файловая версия их не держит, М11 не будет работать по причинам, которые невозможно будет найти.

Поэтому файл на 96 строк кода — самый важный в курсе. Он маленький, потому что обещаний два.

> **Что можно проверить без железа.** Всё. `test_the_config_store_survives_a_restart_and_refuses_a_stale_cas` открывает хранилище дважды, как два процесса; `test_two_processes_one_cas_winner` запускает четыре потока по сорок попыток каждый и проверяет, что счётчик равен числу успешных записей — ни одна не потерялась и ни одна не посчиталась дважды.

## Что нужно знать заранее

- **Урок 1** — контракт и коробка: `Box` создаёт `FileVariables` в `<tmp>/config`.
- Что такое атомарное переименование в POSIX: `os.replace` внутри одной файловой системы либо произошло, либо нет.
- `fcntl.flock` — консультативная блокировка файла, видимая всем процессам на машине.
- Что такое интерфейс как понятие: `interface` в Go, абстрактный класс в C++, `abc.ABC` в Python — любой из трёх достаточен, разницу между ними разберём по ходу.

## Шаг 1 — Два обещания, и что из них следует

Прежде чем писать, выпишем, что должно получиться, в виде разговора двух процессов:

```
A: get("vms/cameras/7")        -> ({"name": "gate"}, 1001)
B: get("vms/cameras/7")        -> ({"name": "gate"}, 1001)
A: put("vms/cameras/7", {...}, cas=1001)  -> 1002        A прочитал, изменил, записал
B: put("vms/cameras/7", {...}, cas=1001)  -> Conflict    B опоздал и узнал об этом
```

Последняя строка — вся суть. B **не** затирает чужое изменение молча; он получает отказ и должен перечитать. Это и есть «одна строка правится по очереди» без единой блокировки в прикладном коде: каждый пишущий говорит, какую версию он видел, и хранилище отказывает тому, кто видел старую.

Отсюда три следствия, которые будут повторяться весь курс. **Контроллер безопасен при двух** — второй просто проиграет гонку. **Эпоха выдаётся без координатора** — `next_epoch` читает, прибавляет единицу и пишет с CAS в цикле, и из четырёх гонящихся выдаются четыре разных числа. **Слот — это доказательство, а не назначение** — воркер не просит имя, он его захватывает.

## Шаг 2 — Каркас файла

Начнём с того, что файл объявляет о себе и своих ошибках:

```python
"""A config store with the semantics Nomad Variables promise — a
raft-assigned ModifyIndex, PUT with cas=<index> succeeding only if the index
still matches, a conflict otherwise — on one box, as files.

One JSON file per path under <root>/vars/, one counter file for the index,
one lock. Every write is atomic (write-then-rename) and serialised by the
lock, so two processes on the same box see exactly what two clients of one
raft would: one of them wins the CAS.
"""
from __future__ import annotations

import fcntl
import json
import os
from typing import Protocol


class Conflict(Exception):
    """The cas index did not match the current ModifyIndex."""


class Forbidden(Exception):
    """This writer may not write that path — one writer per prefix."""
```

Два исключения объявлены сразу, хотя второе понадобится только в уроке 3. Они здесь вместе не по лени: это **два способа, которыми запись может не состояться**, и разница между ними существенна. `Conflict` — «ты опоздал, перечитай и попробуй снова», нормальная часть работы, её ловят и повторяют десятки раз в секунду. `Forbidden` — «тебе сюда нельзя», и повторять бессмысленно: это ошибка конфигурации, которая должна дойти до человека. В М11 первое станет HTTP 409, второе — 403, и семантика не изменится.

Дальше — интерфейс, которым пользуется вся платформа:

```python
Index = str | int


class Variables(Protocol):
    def get(self, path: str) -> tuple[dict | None, Index]: ...
    def put(self, path: str, items: dict, cas: Index | None = None) -> Index: ...
    def list(self, prefix: str) -> list[str]: ...
```

Три метода — и один псевдоним типа, о котором ниже.

### Что такое `Protocol`

Это **структурная типизация**, появившаяся в Python 3.8. Объявляется форма, а не базовый класс: подходит всё, у чего есть `get`, `put` и `list` нужного вида, независимо от того, что оно наследует и слышало ли вообще про это объявление.

Если у вас есть опыт в других языках, ближайшие соответствия такие:

| | что это | кто кого знает |
|---|---|---|
| Go | `interface` | **то же самое**: тип реализует интерфейс молча, объявлять это не нужно |
| C++ | абстрактный класс с чисто виртуальными методами | реализация **обязана** от него наследоваться |
| Python | `abc.ABC` | то же, что в C++: наследование обязательно |

То есть по **роли** `Protocol` — это абстрактный класс: место, где записано, чего платформа ждёт от хранилища. А по **механике** он ближе к `interface` в Go, и именно это здесь и нужно.

Разница не академическая. С абстрактным классом (или с `abc.ABC`) реализация обязана импортировать интерфейс и унаследоваться от него: `class NomadVariables(Variables)`. Значит, М11 зависел бы от М10 не только тем, что использует платформу, но и тем, что его классы объявляют себя её потомками. С `Protocol` `NomadVariables` из М11 подойдёт, **не упоминая это объявление ни строкой**, — и зависимость останется односторонней. Го-порт делает ровно то же самое: там `Variables` — это `interface`, и отдельного слова для «структурно» не требуется, потому что в Go других интерфейсов не бывает.

Цена у этого своя, и её стоит знать: во время выполнения `Protocol` не делает **ничего**. Это не `abc.ABC`, `isinstance` по нему по умолчанию не работает (нужен `@runtime_checkable`, и тогда он проверит только наличие имён, а не сигнатуры). Проверяет его статический анализатор — mypy, pyright. В Go несоответствие интерфейсу поймает компилятор, в C++ — тоже; здесь не поймает никто, кроме проверяльщика типов и тестов. Поэтому рядом с этим объявлением живёт набор тестов на **поведение** — `tests/test_variables_contract.py`, пять пунктов контракта, которые гоняются против любой реализации: форма говорит, что `put` принимает `cas`, но она не в силах сказать, что при несовпадении он обязан бросить `Conflict`, а не записать поверх. Второе и есть настоящий контракт, и выразить его в сигнатуре нельзя — только прогнать.

Тело каждого метода — `...`. Это не «дописать потом»: в протоколе тело не имеет смысла, вызывать его никто не станет.

### Почему индекс — `str | int`

`Index = str | int` — это обещание **не смотреть внутрь**. У Nomad `ModifyIndex` — число, и число провоцирует: сравнить на «больше», вычесть, посчитать, на сколько записей мы отстали. У Kubernetes то же место называется `resourceVersion` и является строкой, которую конвенции его API прямо запрещают интерпретировать.

Платформа поэтому сравнивает индексы **только на равенство** и никогда не упорядочивает и не складывает их. Одна строка типа — и хранилище с любой версией годится; одно `if idx > old` где-нибудь в цикле — и половина систем отпадает навсегда. Наша файловая реализация ниже выдаёт обычные числа (и в её собственных сигнатурах стоит `int`) — но это её частное дело, а не обещание контракта.

Заметьте, чего в интерфейсе нет: `delete` есть у файловой реализации, но в протокол не вынесен, потому что платформа обходится без удаления везде, кроме уборки идемпотентных ключей.

И маленькая функция, которая не даёт ключу уйти из каталога:

```python
def _safe(path: str) -> str:
    if ".." in path or path.startswith("/"):
        raise ValueError(path)
    return path
```

Ключи в этой системе приходят из HTTP-путей (`/cameras/7` → `vms/cameras/7`), поэтому `..` в ключе — не паранойя, а вопрос времени. Проверка одна на файл и стоит ноль.

## Шаг 3 — Раскладка на диске

```python
class FileVariables:
    def __init__(self, root: str, writer: str | None = None, acl: dict[str, list[str]] | None = None):
        self.root = root
        self.dir = os.path.join(root, "vars")
        os.makedirs(self.dir, exist_ok=True)
        self.index_file = os.path.join(root, "index")
        self.lock_file = os.path.join(root, "lock")
        self.writer, self.acl = writer, acl or {}
```

Три вещи на диске: каталог `vars/` с файлом на ключ, файл `index` со счётчиком версий и файл `lock`, на котором берётся блокировка. `writer` и `acl` — заготовка для урока 3; сейчас они не используются ни разу.

Обратите внимание на то, чего в конструкторе **нет**: он ничего не читает. Ни счётчика, ни списка ключей, ни кэша. Открыть хранилище — это `mkdir -p`, и всё. Из этого следует полезное свойство: два объекта `FileVariables` на один каталог, созданные в разных процессах, не имеют общего состояния в памяти, а значит, единственное, что их синхронизирует, — диск. Именно это делает тест из четырёх потоков осмысленным: каждый «процесс» открывает хранилище сам.

## Шаг 4 — Ключ в имя файла

```python
    def _file(self, path: str) -> str:
        return os.path.join(self.dir, _safe(path).replace("/", "%2F") + ".json")
```

Ключ `vms/cameras/7` становится файлом `vms%2Fcameras%2F7.json` в одном плоском каталоге. Не деревом подкаталогов — и это выбор, который стоит объяснить.

Дерево выглядит естественнее: `vars/vms/cameras/7.json`. Но тогда `list("vms/")` — это рекурсивный обход, а создание ключа — это `makedirs` под блокировкой; и появляется случай, которого не хочется: ключ `vms/cameras` и ключ `vms/cameras/7` одновременно, то есть файл и каталог с одним именем. Плоский каталог убирает всё это разом: ключ — это строка, `list` — один `listdir` с фильтром по префиксу, а коллизия имён невозможна, потому что кодирование обратимо.

Цена — уродливые имена в `/tmp` и предел на длину имени файла (255 байт), в который ключи курса не упираются: самый длинный — `platform/resources/<сервер>/heartbeat`.

## Шаг 5 — Блокировка

```python
    def _locked(self):
        f = open(self.lock_file, "a+")
        fcntl.flock(f, fcntl.LOCK_EX)
        return f
```

Четыре строки, и в них важен тип возвращаемого значения: **файловый объект**, который используется как контекстный менеджер. `with self._locked():` берёт блокировку, а выход из блока закрывает файл — и закрытие снимает `flock`. Отдельного `unlock` нет, и забыть его нельзя.

Почему `flock`, а не `threading.Lock`: потому что на коробке это **разные процессы**. `vmscontroller`, `vmsworker@w-1`, `vmsconsole` — это три юнита systemd, и блокировка в памяти одного из них не значит ничего для двух других. `flock` на файле видна всей машине.

Почему `"a+"`: файл открывается на добавление, поэтому создаётся, если его нет, и не обрезается, если есть. Содержимое файла блокировки не читают и не пишут — он нужен только как якорь для `flock`.

Блокировка берётся только на запись (`put`, `delete`). Чтение идёт без неё — и в следующем шаге будет видно, почему это безопасно.

## Шаг 6 — Счётчик версий

```python
    def _next_index(self) -> int:
        try:
            n = int(open(self.index_file).read() or 1000)
        except FileNotFoundError:
            n = 1000
        n += 1
        tmp = self.index_file + ".tmp"
        with open(tmp, "w") as f:
            f.write(str(n))
        os.replace(tmp, self.index_file)
        return n
```

Счётчик один на всё хранилище, а не на ключ. Это копирует raft: в Nomad `ModifyIndex` — это индекс журнала, общий для кластера, поэтому запись в одну переменную двигает индекс, который увидит следующая запись в любую другую. Прикладной код на это не опирается — он всегда сравнивает индекс того же ключа, — но копировать чужую семантику дешевле, чем изобретать похожую.

Две детали. Первая: **начинается с 1000, а не с нуля.** Отсюда `assert idx == 1001` в тесте, и это не косметика. Значение `0` в этом API означает «ключа нет» (см. `get`), а `cas=0` — «создать, только если не существует». Если бы счётчик начинался с нуля, первая же запись получила бы индекс, который нельзя отличить от «нет ключа».

Вторая: счётчик **не сбрасывается при перезапуске**, потому что живёт в файле. Процесс, который читал ключ до перезапуска и пишет с тем же `cas` после, получит `Conflict` — как и должен, потому что за это время всё могло измениться. Счётчик в памяти дал бы после рестарта индексы, совпадающие со старыми, и устаревший CAS прошёл бы.

Функция всегда вызывается под блокировкой. Она не проверяет это — просто зафиксируем как правило файла.

## Шаг 7 — Чтение

```python
    def get(self, path: str) -> tuple[dict | None, int]:
        try:
            with open(self._file(path)) as f:
                d = json.load(f)
        except FileNotFoundError:
            return None, 0
        return dict(d["items"]), int(d["index"])
```

Возвращается пара: содержимое и версия. Отсутствующий ключ — это `(None, 0)`, а не исключение: почти все вызывающие пишут `items, idx = vars.get(path)` и дальше `if items is None`, и версия `0` при этом сразу годится как `cas` для создания.

Чтение **без блокировки**, и это безопасно по единственной причине: запись переименовывает готовый файл на место. Читатель открывает либо старый inode, либо новый; файла, записанного наполовину, не существует в природе. Отсюда же — `dict(d["items"])`: возвращается свежий словарь, чтобы вызывающий мог его менять, не трогая ничего общего.

## Шаг 8 — Запись

Сердце файла. Пока без ACL — он появится в уроке 3:

```python
    def put(self, path: str, items: dict, cas: int | None = None) -> int:
        with self._locked():
            _, current = self.get(path)
            if cas is not None and cas != current:
                raise Conflict(f"{path}: cas={cas} but ModifyIndex={current}")
            idx = self._next_index()
            tmp = self._file(path) + ".tmp"
            with open(tmp, "w") as f:
                json.dump({"items": {k: str(v) for k, v in items.items()}, "index": idx}, f)
            os.replace(tmp, self._file(path))
            return idx
```

Читаем по строкам.

**`with self._locked()`** — всё, что дальше, происходит по одному на машину. Без этого между чтением текущего индекса и записью мог бы вклиниться другой процесс, и оба увидели бы один индекс, оба прошли бы проверку, и одно изменение потерялось бы. Блокировка превращает «прочитать и записать» в одну операцию — то, что в raft даёт консенсус.

**`_, current = self.get(path)`** — текущая версия. Содержимое не нужно, нужен только индекс.

**`if cas is not None and cas != current`** — сама проверка. `cas=None` значит «пиши поверх, мне всё равно»: так пишут heartbeat-подобные вещи, у которых один писатель по построению. `cas=<число>` — «я видел эту версию».

Особый случай, который стоит запомнить: **`cas=0` означает «создать, только если не существует»**, потому что `current` для отсутствующего ключа равен нулю. На этом стоят три места в системе. `SpecController.create` — чтобы две консоли, создающие камеру с одним идентификатором, не затёрли друг друга. `IdempotencyKeys.claim` — чтобы повторный POST не получил вторую заявку. `Worker.claim_slot` — чтобы двое, захватывающих свободное имя, разошлись.

**`idx = self._next_index()`** — новая версия. Берётся после проверки: если проверка не прошла, индекс не тратится.

**`json.dump({"items": {k: str(v) ...}, "index": idx}, f)`** — и здесь прячется решение, о которое спотыкаются. **Все значения приводятся к строке.** `{"revision": 1}` ляжет на диск как `{"revision": "1"}` и прочитается обратно строкой. Это опять копия Nomad: там значение переменной — всегда строка, и ничем другим быть не может.

Жить с этим приходится всей платформе. `Assignment.from_items` разбирает `rev` обратно в `int`, `Slot.from_items` — `at` в `float`, а `"true"`/`"false"` в `bool`; `SubsystemSpec.row` делает то же по типам из YAML. Каждый раз это выглядит лишней работой — ровно до того места, где Variables оказываются настоящими и типов у них нет вовсе.

**`os.replace(tmp, self._file(path))`** — публикация. Запись шла во временный файл, и на место она встаёт одним неделимым действием. Отсюда и право читать без блокировки.

**`return idx`** — новая версия. Вызывающий её обычно запоминает, потому что следующая его запись пойдёт с этим `cas`.

## Шаг 9 — Удаление и перечисление

```python
    def delete(self, path: str, cas: int | None = None) -> None:
        with self._locked():
            _, current = self.get(path)
            if cas is not None and cas != current:
                raise Conflict(f"{path}: cas={cas} but ModifyIndex={current}")
            try:
                os.remove(self._file(path))
            except FileNotFoundError:
                pass
            self._next_index()
```

Та же проверка, потом удаление. Отсутствующий файл — не ошибка: удаление идемпотентно. Индекс тратится (`_next_index()` без использования результата) — счётчик должен двигаться, чтобы устаревший CAS на удалённый и заново созданный ключ не прошёл.

ACL здесь не проверяется. В курсе `delete` вызывается из одного места — уборки идемпотентных ключей, — и вызывается токеном, которому этот префикс и так разрешён.

```python
    def list(self, prefix: str) -> list[str]:
        out = []
        for f in os.listdir(self.dir):
            if f.endswith(".json"):
                p = f[:-5].replace("%2F", "/")
                if p.startswith(prefix):
                    out.append(p)
        return sorted(out)
```

Один `listdir`, обратное кодирование, фильтр, сортировка. Фильтр по `.json` отбрасывает `.tmp`-файлы записи, идущей прямо сейчас. Результат отсортирован — вызывающие на это опираются: `Controller.slots()` хочет `w-1, w-2, w-10` в предсказуемом порядке, а тесты сравнивают списки целиком.

Вызывают `list` с префиксом, кончающимся на `/`: `"vms/workers/"`, `"vms/slots/"`, `"vms/idem/"`. Без слэша `"vms/cam"` совпал бы и с `vms/cameras/7`, и с гипотетическим `vms/campaign` — в этой системе таких пар нет, но правило дешевле проверки.

## Шаг 10 — Тест: перезапуск и устаревший CAS

```python
def test_the_config_store_survives_a_restart_and_refuses_a_stale_cas():
    box = Box()
    idx = box.vars.put("vms/cameras/7", {"name": "gate", "revision": 1}, cas=0)
    assert idx == 1001
    again = FileVariables(box.vars.root)                       # a new process, same directory
    items, idx2 = again.get("vms/cameras/7")
    assert items == {"name": "gate", "revision": "1"} and idx2 == idx
    try:
        again.put("vms/cameras/7", {"name": "x"}, cas=idx - 1); raise AssertionError("must conflict")
    except Conflict:
        pass
    assert again.put("vms/cameras/7", {"name": "x"}, cas=idx) == 1002
    assert again.list("vms/") == ["vms/cameras/7"] and again.get("nope") == (None, 0)
```

Пять утверждений, и каждое — про отдельное обещание. `idx == 1001` — счётчик начинается с 1000. `FileVariables(box.vars.root)` — второй объект на тот же каталог: это и есть «другой процесс» в тесте, и он видит то, что записал первый. `revision` вернулась строкой `"1"`, хотя записывали число — то самое приведение к строке, показанное явно, чтобы дальше в курсе оно никого не удивляло. `cas=idx - 1` — версия, которой уже нет, и это `Conflict`. `cas=idx` — та самая, и она проходит, отдавая 1002.

Последняя строка проверяет две мелочи разом: `list` с префиксом видит ключ, а отсутствующий ключ — это `(None, 0)`.

## Шаг 11 — Тест: четверо гонятся, побеждает один

```python
def test_two_processes_one_cas_winner():
    box = Box()
    results = []
    def race(n):
        v = FileVariables(box.vars.root)                       # each "process" opens the store itself
        for _ in range(40):
            items, idx = v.get("counter")
            try:
                v.put("counter", {"n": int(items["n"]) + 1 if items else 1}, cas=idx); results.append(n)
            except Conflict:
                pass
    ts = [threading.Thread(target=race, args=(i,)) for i in range(4)]
    [t.start() for t in ts]; [t.join() for t in ts]
    n = int(box.vars.get("counter")[0]["n"])
    assert n == len(results)                                   # every successful write counted exactly once
```

Четыре потока, каждый со своим объектом хранилища, каждый делает сорок раз «прочитай, прибавь, запиши с CAS» и считает свои успехи. Проверяется не то, что успехов 160, — их меньше, часть попыток проиграет и будет отброшена. Проверяется равенство: **значение счётчика равно числу успешных записей.**

Это утверждение ловит обе возможные поломки сразу. Если бы CAS не работал и потерянное обновление проходило, успехов было бы больше, чем значение. Если бы блокировка пропускала двоих в критическую секцию, два потока прочитали бы одно `n`, оба записали бы `n+1`, оба посчитали бы успех — и значение отстало бы. Одно сравнение, два дефекта.

Заметьте, что тест **не повторяет** проигравшие попытки. Настоящий код повторяет — `Controller.write` и `next_epoch` крутят цикл до успеха, — но тест специально оставляет отказы отказами, потому что проверяет само правило, а не удобство поверх него.

**Результат:** `variables.py` на 96 строк кода; оба теста зелёные; и ответ своими словами на вопрос «почему читать можно без блокировки, а писать нельзя».

## Что может пойти не так

| Симптом | Скорее всего |
|---|---|
| `Conflict` там, где писатель один | Записали с `cas` от старого чтения — между ними был ещё один `put` того же процесса. Правило: `cas` берётся из чтения, которое случилось **в этой же** попытке, а не запоминается надолго. |
| Первая запись возвращает 1, а не 1001 | Счётчик начали с нуля. Тогда `cas=0` перестаёт означать «создать, только если нет», и `create` двух консолей начнёт затирать друг друга. |
| Значения возвращаются не тех типов | Так и есть: всё хранится строками. Разбирают их `Assignment.from_items`, `Slot.from_items` и `SubsystemSpec.row`. Не чините это в хранилище — в М11 типов не будет тем более. |
| Гонка иногда теряет обновление | Между `get` и `put` нет блокировки, или `_next_index` вызывается снаружи неё. Проверка версии и присвоение новой должны быть в одной критической секции. |
| В каталоге растут `.tmp`-файлы | Процесс падает между `open(tmp)` и `os.replace`. Это безвредно — `list` их не видит, а следующая запись того же ключа перезапишет, — но большое их число означает, что кто-то падает регулярно. |
| Хранилище «пустое» после перезапуска | Разные `root` у двух процессов. `Box` кладёт его в `<tmp>/config`, юниты — в `/data/platform/config`; каталог должен быть на разделе данных, а не в слоте образа. |
| `list("vms")` возвращает лишнее | Префикс без завершающего слэша. Вызывайте `list("vms/")`. |

## Итог

- Хранилище копирует два обещания Nomad Variables: растущий `ModifyIndex` и `PUT` с `cas`, проходящий только при совпадении. Больше оно не обещает ничего.
- Запись атомарна, потому что идёт через временный файл и `os.replace`; поэтому чтение не нуждается в блокировке.
- Блокировка — `flock` на файле, то есть видна всем процессам коробки, а не только потокам одного.
- Счётчик версий один на хранилище, начинается с 1000 и переживает перезапуск. Ноль зарезервирован под «ключа нет», и `cas=0` означает «создать, только если нет».
- Все значения — строки, на входе и на выходе. Разбор типов живёт выше.
- `Variables` объявлен через `Protocol` — это `interface` в Go по механике и абстрактный класс по роли: реализация подходит по форме и не обязана ничего наследовать, поэтому зависимость между модулями остаётся односторонней. Платит за это тем, что во время выполнения не проверяется ничего.
- Индекс объявлен как `Index = str | int` и сравнивается только на равенство: у Nomad это число, у Kubernetes — строка, которую запрещено интерпретировать. Одно `>` в цикле — и половина хранилищ перестаёт подходить.
- `Conflict` — нормальная часть работы, её повторяют; `Forbidden` (урок 3) — ошибка конфигурации, её показывают человеку.
- Один тест с четырьмя потоками ловит и потерянное обновление, и дырявую блокировку — потому что сравнивает счётчик с числом успехов.
