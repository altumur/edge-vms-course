# Урок 13 — `SpecController` III: молчания, ручки, снимок

**Модуль:** М10A — Платформа (ServerVMS, часть первая)
**Вы напишете:** вторую половину контроллера — три способа потерять место, ручку администратора, перераспределение и перебалансировку, — и то, что уезжает наружу: модель чтения, снимок и измеренное время переключения. После этого урока подсистема `counter` запускается целиком.
**Время:** ~90 минут.

## Зачем этот урок

Размещение из урока 12 ставит единицу туда, где есть место, и больше её не трогает. Правило «добавление воркера ничего не двигает» держится ровно до тех пор, пока место, куда поставили, никуда не девается. А оно девается — тремя разными способами, и различить их важнее, чем отреагировать.

**Воркер сказал, что уходит.** Планировщик уменьшил `count`, оператор увёл сервер. Слот отпущен (урок 7), назначение осталось. Это событие, о котором система знает точно, потому что ей сказали.

**Сервер перестал отвечать.** Воркер на нём жив и бьётся, но ресурс, к которому он пишет, замолчал. Ему некуда работать, хотя сам он в порядке. Различие тонкое и в М10B станет решающим.

**Машина исчезла.** И воркер молчит, и ресурс молчит — два молчания из разных процессов одной машины. Одно молчание, как мы решили в уроке 7, не толкуется; два — уже факт о машине.

И есть четвёртый случай, который не является потерей места вовсе: **администратор передумал.** Он решил, что на одном сервере работу несёт один воркер, а не все, сколько их туда попало. Это ручка, а не событие, и она в том же уроке, потому что влияет на тот же пул.

> **Что можно проверить без железа.** Всё, включая три молчания. Часы поддельные, ресурсы — это heartbeat-объекты, которые тест пишет сам. В М10B это `test_lesson6_controller.py` и `test_lesson4_failover.py` в М11: «одно молчание ничего не двигает, два двигают».

## Что нужно знать заранее

- **Урок 7** — `released` против `lapsed` и почему крах не толкуется.
- **Урок 12** — `_pool`, `_pick`, `move`, причина размещения.
- **Урок 4** — heartbeat ресурса: `platform/resources/<сервер>/heartbeat`.

## Шаг 1 — Ручка администратора

```python
    POLICY_CHOICES = {"servers": ("distinct", "shared")}

    @property
    def POLICY_DEFAULTS(self) -> dict:
        return {"servers": self.spec.servers}

    def policy(self) -> dict:
        items, _ = self.vars.get(self.sub.config("policy"))
        out = dict(self.POLICY_DEFAULTS)
        for k, v in (items or {}).items():
            if k in self.POLICY_CHOICES and v in self.POLICY_CHOICES[k]:
                out[k] = v
        return out
```

Одна ручка на весь курс, и у неё два положения. **`shared`** — на одном сервере может работать сколько угодно воркеров, и все несут единицы. **`distinct`** — на сервере работает один несущий воркер; остальные, попавшие туда, простаивают.

Умолчание приходит **из спецификации**, а не из константы: `placement.servers` в YAML. Так у камер `shared` (коробка — это несколько воркеров на одном сервере, и это нормально), а у записей `distinct` (второй регистратор на тех же дисках — не второе место для записи). Одна ручка, два разумных умолчания, и оба записаны там же, где остальное описание подсистемы.

Чтение **снисходительно**: неизвестный ключ и неизвестное значение молча игнорируются, и возвращается умолчание. Строка в хранилище, испорченная чужой правкой или оставшаяся от старой версии, не может сломать проход контроллера.

```python
    def set_policy(self, changes: dict) -> dict:
        for k, v in changes.items():
            if k not in self.POLICY_CHOICES or v not in self.POLICY_CHOICES[k]:
                raise Refused(f"policy {k} must be one of {', '.join(self.POLICY_CHOICES.get(k, ()))}")
        self.write(self.sub.config("policy"), lambda it: {**(it or {}), **{k: str(v) for k, v in changes.items()}})
        return self.policy()
```

Запись **строгая**: неизвестное значение — `Refused` с перечислением допустимых. Асимметрия сознательная и повторяет линию урока 10: человеку, который ошибся **сейчас**, говорят сразу; данные, которые уже лежат, не должны ломать работу.

Возвращается `policy()`, а не то, что записали: администратор видит полный набор ручек после правки, включая те, которых не трогал.

## Шаг 2 — Кто простаивает по политике

```python
    def idle_by_policy(self, workers) -> list[str]:
        if self.policy()["servers"] != "distinct":
            return []
        by_server: dict[str, list[str]] = {}
        for w in sorted(workers, key=slot_number):
            by_server.setdefault(self.server_of(w), []).append(w)
        idle = []
        for server, ws in by_server.items():
            if server == "?" or len(ws) < 2:
                continue
            keep = max(ws, key=lambda w: (self.load(w), -slot_number(w)))
            idle += [w for w in ws if w != keep]
        return idle
```

При `shared` — пустой список, и дальше ничего не считается.

При `distinct` воркеры группируются по серверам, и на каждом сервере с двумя и более остаётся один: **тот, у кого больше загрузка, а при равной — с меньшим номером слота.**

Оба критерия нужны. Первый — «остаётся тот, кто уже работает»: если `w-1` несёт двадцать камер, а `w-4` только что приехал на тот же сервер, простаивать должен приезжий, иначе двадцать камер поедут без всякой пользы. Второй — детерминированность: при равной загрузке (обычно нулевой) выбор не должен зависеть от порядка обхода, иначе два контроллера решат по-разному.

`server == "?"` — воркеры, чьего сервера мы не знаем (не бились ни разу), пропускаются: складывать их в одну корзину было бы неверно, это разные неизвестности.

Заметьте, что метод возвращает **кого исключить**, а не кого оставить. Так его удобнее складывать с другим исключением в пуле.

## Шаг 3 — Три состояния ресурса

```python
    def resource_state(self, server: str, lost_after: float = 45.0) -> str:
        from .resource import resources_seen
        hb = resources_seen(self.objects).get(server)
        if hb is None:
            return "unknown"
        return "live" if self.wall() - float(hb["ts"]) <= lost_after else "silent"
```

Три значения, и среднее из них — **`unknown`** — важнее двух крайних.

`live` — ресурс на этом сервере бился недавно. `silent` — бился, но давно. `unknown` — **не бился никогда**, мы про него ничего не знаем.

Разница между `silent` и `unknown` — это разница между «замолчал» и «не запускался», и она определяет, действовать ли. Замолчавший ресурс был и пропал: место, которое было, исчезло, и это повод. Неизвестный ресурс, возможно, просто ещё не стартовал — а на коробке, где процесс ресурса появился в М10B позже воркера, так бывает при каждом первом запуске. Считать `unknown` за `silent` значило бы отказываться размещать на свежей коробке, пока не поднимется каждый процесс.

Поэтому правило, которое проходит через весь оставшийся код: **исключает только `silent`.** Формулировка «неизвестность — не повод действовать» — из той же семьи, что «одно молчание не толкуется».

Ленивый импорт `resources_seen` внутри метода — из-за кругового импорта: `resource.py` пользуется спецификацией. Один такой импорт в платформе на весь курс, и стоит он одной строки.

```python
    def without_resource(self, workers) -> list[str]:
        if self.spec.requires != "resource":
            return []
        return [w for w in workers if self.resource_state(self.server_of(w)) == "silent"]
```

Проверка включается только для подсистем, объявивших `requires: resource` в YAML. Для `counter` она не нужна: тик не пишет на диск, и молчащий ресурс ему безразличен. Для камер и записей — нужна.

## Шаг 4 — Два молчания

```python
    def gone_servers(self, lost_after: float = 45.0) -> dict[str, str]:
        """Lapsed slots whose server's resource is silent too: {slot: server}."""
        if self.spec.requires != "resource" or self.policy()["servers"] != "distinct":
            return {}
        now = self.wall(); out = {}
        for name, slot in self.slots().items():
            if slot.lapsed(now) and now > slot.until + lost_after and self.assignment(name).units:
                server = self.server_of(name)
                if server != "?" and self.resource_state(server, lost_after) == "silent":
                    out[name] = server
        return out
```

Единственное место в системе, где контроллер действует **по молчанию**, — и посмотрите, сколько условий на это навешано.

Первое: подсистема требует ресурса. Если ей всё равно, где работать, отсутствие сервера не мешает — планировщик перезапустит процесс где-нибудь ещё.

Второе: политика `distinct`. При `shared` умерший сервер — забота планировщика: он поставит замену на соседний, та возьмёт слот и унаследует назначение (урок 7). Вмешиваться незачем. А при `distinct` замена, приехавшая на соседний сервер, **будет простаивать по политике** — и работа не тронется с места, пока кто-нибудь её не перенесёт.

Третье: слот просрочен — **и просрочен ещё на один `lost_after` сверх того**. Это отсрочка, данная планировщику: сорок пять секунд на то, чтобы слот лапсировался, и ещё сорок пять на то, чтобы он поставил замену. Если за полторы минуты никто не пришёл, никто и не придёт.

Четвёртое: у слота есть назначение. Пустой слот двигать незачем.

Пятое: сервер известен и его ресурс **молчит** — не `unknown`, именно `silent`.

Пять условий, и это правильная цена. Ошибка здесь стоит переезда работы туда, откуда она через минуту поедет обратно, — то есть двух разрывов записи вместо нуля.

Возвращается `{слот: сервер}`, потому что причина будет называть и то, и другое: человеку нужно знать, какая машина исчезла, а не только чьи единицы поехали.

## Шаг 5 — Пул, собранный целиком

```python
    def _pool(self, workers):
        pool = sorted(workers if workers is not None else self.workers_seen())
        gone = set(self.without_resource(pool)) | set(self.idle_by_policy(pool))
        return [w for w in pool if w not in gone]
```

Теперь метод из урока 12 читается полностью: живые, минус те, чей ресурс замолчал, минус те, кого политика оставила простаивать. Обе группы вычитаются **до** выбора, и потому ни в `_best`, ни в `_pick` нет ни одной проверки про ресурсы и политику. Каждое решение принимается в одном месте.

## Шаг 6 — Перераспределение

```python
    def redistribute(self, workers: list[str] | None = None) -> list[tuple]:
        self.unplace_deleted()
        moves = []
        seen = sorted(workers if workers is not None else self.workers_seen())
        gone_for = {g: f"slot {g} released" for g in self.released_slots()}
        for w in self.without_resource(seen):
            if self.assignment(w).units:
                gone_for.setdefault(w, f"resource on {self.server_of(w)} silent")
        for w, server in self.gone_servers().items():
            gone_for.setdefault(w, f"server {server} gone: slot {w} lapsed and its resource silent")
```

Сначала собирается словарь «откуда уносим → почему», и в нём три источника ровно из шага «Зачем». Порядок важен: `setdefault` не перезаписывает, поэтому воркер, попавший в список отпущенных, сохранит причину «слот отпущен», даже если он заодно без ресурса. Наиболее определённая причина выигрывает.

Каждая причина — **готовое предложение на человеческом языке**, и в этом видно, чему курс придаёт значение: `server srv-a gone: slot w-1 lapsed and its resource silent` — это ответ на вопрос «почему камера уехала», данный до того, как его задали.

```python
        for gone, why in gone_for.items():
            live = [w for w in self._pool(workers) if w != gone]
            for unit in sorted(self.assignment(gone).units, key=_unit_key):
                uid = self.spec.parse_id(unit)
                row = self.unit(uid)
                pool = self.eligible(row, live) if row else live
                best, free, near = self._pick(pool, uid)
                if best is None:
                    break
                self.move(uid, best, f"{why}; most free capacity ({free}); on {self.server_of(best)}{near}")
                moves.append((uid, gone, best))
        return moves
```

Дальше — тот же выбор, что в уроке 12: пул, ограничение, близость. Причина склеивается из двух частей: **почему уносим** и **почему принесли именно сюда**.

`break` при `best is None` — не `continue`. Если некуда деть эту единицу, остальным из того же назначения тоже некуда: пул один. Единицы остаются там, где были, и это честнее, чем снять их в никуда: строка размещения продолжает указывать на мёртвого воркера, консоль показывает это, а следующий проход попробует снова, когда появится место.

Строка размещения при этом **не обнуляется**. Единица числится там, где её последний раз разместили, — и если воркер вернётся (просрочка, а не уход), он её подберёт, ничего не потеряв.

## Шаг 7 — Перебалансировка по просьбе

```python
    def rebalance(self, budget: int, dead_band: float | None = None, workers: list[str] | None = None) -> list[tuple]:
        dead_band = self.spec.dead_band if dead_band is None else dead_band
        workers = self._pool(workers)
        moves = []
        for _ in range(budget):
            if len(workers) < 2:
                break
            loads = {w: self.load(w) / self.capacity_of(w) for w in workers}
            hi, lo = max(workers, key=loads.get), min(workers, key=loads.get)
            if loads[hi] - loads[lo] < dead_band:
                break
            cands = sorted(self.assignment(hi).units, key=_unit_key)
            if not cands or self.load(lo) + 1 > self.capacity_of(lo):
                break
            uid = self.spec.parse_id(cands[0])
            self.move(uid, lo, f"rebalance from {hi} (spread {(loads[hi] - loads[lo]) * 100:.0f}%)")
            moves.append((uid, hi, lo))
        return moves
```

Три ограничителя, и каждый защищает от своей беды.

**Бюджет.** Число перемещений, заданное вызывающим. Не «выровнять», а «сделать не больше стольких шагов». Оператор, нажавший кнопку, получает предсказуемое количество разрывов записи, а не «сколько понадобится».

**Мёртвая зона.** Пока разница загрузок меньше десяти процентов, ничего не двигается. Без неё перебалансировка гонялась бы за идеалом, перекладывая единицы туда-сюда ради процента.

**Проверка вместимости.** Если у наименее загруженного нет места даже на одну, выход. Без неё можно было бы переложить туда, откуда придётся класть обратно.

И самое важное — **этого метода нет в проходе контроллера**. `ensure_placed` и `redistribute` вызываются каждые пять секунд; `rebalance` вызывается только когда попросили. Разница в том же, о чём говорил урок 12: система, которая двигает работу по своему усмотрению, теряет запись в моменты, которых оператор не ждал.

Причина называет разброс в процентах — то число, которое оператор увидел на странице перед нажатием.

## Шаг 8 — Модель чтения

```python
    def read_model(self, lost_after: float = 45.0) -> list[dict]:
        now = self.wall()
        rows = []
        for w, hb in self.workers_seen(max_age=1e12).items():
            age = now - hb.ts
            state = "live" if age <= lost_after else "stale"
            for s in hb.status:
                rows.append({**s, "worker": w, "server": hb.extra.get("server", "?"), "age": round(age, 1), "worker_state": state})
        return sorted(rows, key=lambda r: _unit_key(str(r["id"])))
```

То, что видит человек на странице: строка на **наблюдение**, собранная из heartbeat'ов всех воркеров. К тому, что сказал воркер, добавляются четыре поля: кто сказал, на каком сервере, сколько секунд назад и живой ли он сейчас.

Возраст берётся **без ограничения** (`max_age=1e12`), а состояние вычисляется отдельно. Это ровно то же решение, что в уроке 12 с ёмкостью: устаревшие данные **показываются со своим возрастом**, а не прячутся. Оператор, у которого воркер молчит две минуты, должен видеть последнее, что тот сказал, и метку `stale` рядом, — а не пустую страницу.

Обратите внимание: модель чтения строится из наблюдений, а не из конфигурации. Строка, которую никто не наблюдает (единица не размещена, или её воркер не бился ни разу), в ней **не появится** — и консоль поэтому показывает две вещи рядом: `rows` (что наблюдается) и `configured` (что настроено). Разница между ними — это и есть «настроено, но не работает».

## Шаг 9 — Снимок

```python
    def snapshot(self) -> dict:
        """Units and placement as one object: what the layer above reads. A copy
        with an age — never the rows themselves, which do not leave raft."""
        keep = ["id"] + [f for f in self.spec.snapshot if f != "id"] + ["revision"]
        units = []
        for r in self.units():
            w = self.where(r["id"])
            units.append({**{k: r[k] for k in keep if k in r}, "worker": w, "server": self.server_of(w or "")})
        return {"cluster": self.cluster, "ts": self.wall(), self.spec.rows: units}

    def publish_snapshot(self) -> None:
        import json
        self.objects.put(self.sub.config("snapshot"), json.dumps(self.snapshot()).encode())
```

Единственное, что покидает кластер. Поля отбираются по списку `snapshot` из YAML — плюс идентификатор и ревизия всегда — и к каждой единице добавляется, где она сейчас.

Docstring называет суть: **копия с возрастом, а не сами строки.** `ts` в снимке — это момент, когда его собрали, и слой выше (домен М12) обязан на него смотреть: то, что он читает, устарело ровно на столько. Строки не покидают raft никогда, потому что у них один писатель и он здесь; то, что уезжает, — производное, и его старость видна.

Публикуется в **объектное** хранилище (урок 4): пишется целиком, читается целиком, версия не нужна. Раз в проход контроллера, то есть каждые пять секунд.

> **Одним объектом — пока.** Здесь снимок пишется в один ключ на весь кластер, и это единственное место в платформе, где данные растут вместе с кластером, а не вместе со своим писателем. У объектного хранилища есть потолок, и на проектных 600 камерах этот объект в него не влезает. Нарезка по воркеру — **урок 25**; до него форма остаётся такой, чтобы было видно, откуда взялась проблема.

Отбор полей по списку — способ подсистемы сказать, чего наружу отдавать не надо. Камера, к примеру, не отдаёт свой источник целиком, если в нём мог оказаться адрес с учётными данными.

## Шаг 10 — Измеренное переключение

```python
    def failover_seconds(self) -> dict[str, float]:
        """Per worker: the gap between the heartbeat before its current instance
        started and that instance's first — measured from what the workers wrote."""
        out = {}
        for w, hb in self.workers_seen(max_age=1e12).items():
            started = float(hb.extra.get("started", hb.ts))
            prev = float(hb.extra.get("previous_hb", 0) or 0)
            if prev:
                out[w] = round(started - prev, 1)
        return out
```

Сколько секунд прошло между последним сигналом **предыдущего** экземпляра слота и первым сигналом нынешнего.

Откуда берутся эти числа: при старте воркер читает heartbeat, лежащий под его именем (урок 8), и, если он написан другим экземпляром, запоминает его время как `previous_hb`, а своё — как `started`. Обе величины он публикует в своём heartbeat'е. Контроллер просто вычитает.

Смысл в том, **кто измеряет**. Не контроллер по своим часам, не монитор снаружи — сам воркер, по тому, что осталось на диске от его предшественника. Это время от «прошлый замолчал» до «нынешний заговорил», то есть настоящий провал в работе, и в М11 оно становится числом в паспорте продукта: `vms_failover_seconds{kind="worst"}`.

`if prev` отбрасывает воркеров, у которых предшественника не было: первый запуск переключением не является.

## Шаг 11 — `counter` запускается

Контроллер закончен, и подсистема из урока 9 теперь работает целиком. Воркер для неё — сорок строк на базе из урока 8:

```python
class CounterWorker(Worker):
    def __init__(self, *a, **kw):
        super().__init__(*a, **kw); self.claim_slot(); self.running = {}
    def reconcile_once(self, now):
        rows = {r["id"]: r for u in self.assignment().units
                for r in [Row(self.vars.get(SPEC.sub.config("ticks", u))[0])] if r}
        for uid in list(self.running):
            if uid not in rows: self.running.pop(uid); self.release(str(uid))
        for uid, r in rows.items():
            if uid not in self.running and r["enabled"]:
                self.take_epoch(str(uid))
                if self.may_write(str(uid)): self.running[uid] = r
        return sorted(self.running)
    def heartbeat_once(self):
        self.heartbeat([{"id": u, "phase": "running", "epoch": self.epochs[str(u)]} for u in self.running],
                       server=self.server, capacity=self.capacity, headroom=self.capacity - len(self.rows))
```

И вся система:

```python
ctl = SpecController(SPEC, vars_.as_writer("countercontroller", SPEC.acl_controller()), objects)
con = SpecController(SPEC, vars_.as_writer("counterconsole",    SPEC.acl_console()),    objects)
w   = CounterWorker(SPEC.sub, None, vars_.as_writer("counterworker", SPEC.sub.acl_worker()), objects)
w.heartbeat_once()
con.create({"name": "первый", "every": 5})       # оператор создал единицу — через свой токен
ctl.ensure_placed()                              # контроллер разместил её — через свой
w.reconcile_once(0)                              # воркер прочитал назначение и взял эпоху
```

Три токена, три роли, ни одной строки платформы, написанной ради счётчика. Уберите воркера, подождите — единица останется размещённой на просроченном слоте. Скажите `w.release_slot()` — и `redistribute` унесёт её к соседу с причиной `slot w-1 released`. Поставьте `servers: distinct` и приведите второго воркера на тот же сервер — он будет простаивать.

Это и есть демонстрация, ради которой модуль отделён: **всё поведение системы уже существует, и камеры к нему не имеют отношения.**

**Результат:** контроллер целиком; работающий `counter` из YAML и сорока строк; и написанное своими словами объяснение, почему `unknown` не считается за `silent`, а одно молчание — за два.

## Что может пойти не так

| Симптом | Скорее всего |
|---|---|
| На свежей коробке ничего не размещается | `unknown` считается за `silent`. Ресурс ещё не стартовал — это не повод отказывать. |
| Работа уехала и через минуту вернулась | Сработало `gone_servers` без отсрочки в один `lost_after`. Планировщику надо дать шанс. |
| При `shared` умерший сервер двигает работу | `gone_servers` не проверяет политику. При `shared` замена приедет на соседний сервер и всё подберёт сама. |
| При `distinct` работа встала после смерти сервера | Обратное: `gone_servers` не срабатывает. Замена простаивает по политике, и двигать должен контроллер. |
| Простаивает тот, кто нёс двадцать единиц | В `idle_by_policy` потерян критерий загрузки. Остаётся тот, кто уже работает. |
| Два контроллера оставляют разных воркеров | Потерян второй критерий (`-slot_number`). При равной загрузке выбор обязан быть детерминированным. |
| Перебалансировка идёт сама | `rebalance` попал в проход контроллера. Он вызывается только по просьбе. |
| Перекладывание туда-сюда | Мёртвая зона нулевая или слишком мала. |
| Страница пустеет, когда воркер молчит | В `read_model` появился возраст-фильтр. Показывать надо последнее сказанное, с меткой `stale`. |
| Домен М12 показывает свежие данные как устаревшие | Он не смотрит на `ts` снимка — или контроллер не публикует его каждым проходом. |

## Итог

- Место теряется тремя способами: воркер сказал, ресурс замолчал, машина исчезла. Различить важнее, чем отреагировать.
- Ручка читается снисходительно и пишется строго: испорченные данные не ломают проход, ошибка человека называется сразу.
- Умолчание политики приходит из спецификации: у камер `shared`, у записей `distinct`.
- Три состояния ресурса, и действовать можно только на `silent`. `unknown` — это «не знаем», и это не повод.
- По молчанию контроллер действует в единственном месте, и там пять условий, включая отсрочку планировщику.
- При `shared` умерший сервер — забота планировщика; при `distinct` — контроллера, потому что замена простаивала бы.
- Причина перераспределения склеивается из «почему уносим» и «почему принесли сюда».
- Некуда деть одну — значит, некуда деть и остальные: `break`, и строка размещения не обнуляется.
- Перебалансировка только по просьбе, с бюджетом и мёртвой зоной; в проходе её нет.
- Наружу уезжает копия с возрастом, а не строки. Время переключения измеряют сами воркеры, а не наблюдатель.
