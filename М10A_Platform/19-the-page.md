# Урок 19 — Страница

**Модуль:** М10A — Платформа (ServerVMS, часть первая)
**Вы напишете:** `w2cplatform/console.html` — 666 строк без единой зависимости: список и формы, собранные из `/spec`; таймлайн на абсолютном позиционировании; события всех подсистем, покрашенные по подсистемам; плеер, идущий по сегментам; живая картинка через WHEP и живая лента событий рядом с ней; переключатели оператора и администратора.
**Время:** ~100 минут.

## Зачем этот урок

Последний урок модуля, и единственный, в котором нет Python. Он здесь не для полноты: страница — это **последняя проверка того, что платформа действительно ничего не знает о подсистеме**.

Пока всё было на сервере, это утверждение держалось на двух тестах чистоты. Но экран — то место, где абстракции ломаются первыми: достаточно одного `if (subsystem === 'vms')`, одной колонки «Адрес камеры», одного захардкоженного `/cameras` — и граница, которую восемнадцать уроков держали, пробита в разметке.

Поэтому у страницы есть свой тест, и он буквальный: **слова `camera` нет во всём файле, кроме вводного комментария.** Страница знает `spec.rows`, `spec.fields`, `spec.media` — и всё. Одна и та же страница обслуживает камеры, записи, детекторы и счётчик тиков из урока 13.

Второе, что делает этот урок, — показывает, сколько на самом деле стоит такой интерфейс. Ни сборки, ни фреймворка, ни `node_modules`, ни шага компиляции. Один файл, который сервер отдаёт как есть. Это не аскеза: коробка с камерами живёт годами, и всё, что требует пересборки, однажды не пересоберётся.

> **Проверка без железа.** `test_the_console_over_http` поднимает консоль на настоящем порту, запрашивает `/`, убеждается, что страница пришла, и ищет в ней слово *camera*. Таймлайн и плеер проверяются в М10B, где появляются `/timeline` и `/segment`.

## Шаг 1 — Палитра и две темы

```css
  :root { --bg:#fff; --fg:#1b1b1b; --muted:#6b6b6b; --line:#d8d8d8; --media:#3b7dd8; --events:#c58a1a; --fenced:#b0b0b0; --live:#2a9d5c; --stale:#c0392b; }
  @media (prefers-color-scheme: dark) { :root { --bg:#151515; --fg:#e8e8e8; --muted:#9a9a9a; --line:#333; --fenced:#555; } }
```

Девять переменных, и почти каждая — не украшение, а **значение**:

| Переменная | Что означает |
|---|---|
| `--media` | синий: интервал, в котором есть запись |
| `--events` | янтарный: интервал без записи, но с событиями; и метки событий |
| `--fenced` | серый: данные, отсечённые эпохой (урок 6) |
| `--live` | зелёный: воркер бьётся, фаза `running` |
| `--stale` | красный: молчит, отказ, ошибка |

Тёмная тема переопределяет **четыре** переменные из девяти. Цвета-значения (`--media`, `--events`, `--live`, `--stale`) в обеих темах одинаковы: синий означает «записано» независимо от того, какой у оператора фон. Переопределяются только цвета-поверхности. Это то различение, из-за которого тёмные темы обычно и разъезжаются.

`prefers-color-scheme` без переключателя: тему выбирает система. Переключатель — это состояние, состояние надо где-то хранить, а хранить его в браузере оператора на посту, где смена меняется каждые восемь часов, бессмысленно.

```css
  body { margin:0; font:14px/1.45 system-ui, sans-serif; color:var(--fg); background:var(--bg); display:grid; grid-template-columns: 280px 1fr; min-height:100vh; }
```

Две колонки: 280 пикселей под список и остальное под главное. Никакой адаптивности к телефону: консоль VMS смотрят на посту, на мониторе, и вёрстка под пять размеров экрана здесь — работа, которую никто не увидит.

`system-ui` — шрифт, который уже есть. Ни одного `@font-face`: коробка может стоять в сети без выхода наружу, и страница, ждущая шрифт с чужого домена, на ней показывается через таймаут.

```js
async function loadSpec() {

```

Первая функция, и она задаёт всю страницу. Разберём по строкам, потому что каждая закрывает одно решение.

`document.title` — вкладка называется по подсистеме. Оператор, у которого открыты `vms` и `det`, различает их по вкладкам.

`spec.rows` в заголовке: «cameras», «recordings», «units», «ticks». Не «Units», не «Элементы» — то самое слово, которое подсистема написала в своей YAML.

Подсказка у формы добавления зависит от `spec.id`: при `numeric` идентификатор даёт контроллер (урок 11), при именованном — сам оператор в поле. Разные сценарии, разные подсказки, и обе взяты из описания.

`#media` и кнопка `#live` показываются только при `spec.media`. У счётчика тиков нет видео — и у страницы счётчика нет ни таймлайна, ни плеера. Не отключено, а отсутствует.

Два списка полей различаются двумя фильтрами. `enabled` исключено везде: у него свой переключатель, потому что галочка в форме требует нажать «Сохранить», а выключить камеру хочется одним кликом. Поле идентификатора исключено из формы правки: имя единицы — это её адрес, и правка адреса — это удаление плюс создание, а не редактирование.

```js
function input(f, adding) {
  const attrs = `name="${f.name}"${f.required && adding ? ' required' : ''}`;
  if (f.type === 'bool') return `<label>${f.name} <input type="checkbox" ${attrs} ${f.default ? 'checked' : ''}></label>`;
  if (f.type === 'int' || f.type === 'float') return `<label>${f.name} <input type="number" ${attrs} ${f.type === 'float' ? 'step="any"' : ''} ${adding && f.default != null ? `value="${f.default}"` : ''} style="width:6em"></label>`;
  const ph = f.type === 'list' ? 'a, b' : (adding && f.default ? String(f.default) : '');
  return `<label>${f.name}${f.type === 'list' ? ' (comma-separated)' : ''} <input type="text" ${attrs} placeholder="${ph}"></label>`;
}
```

Четыре типа из урока 9 превращаются в три вида полей. `bool` → галочка, `int`/`float` → числовое (`step="any"` для дробного, иначе браузер откажется принять `1.5`), всё остальное → текстовое.

`required` **только при добавлении**. При правке пустое поле означает «не менять» — это видно в `fields()` дальше, — и `required` тогда заставлял бы переписывать то, что менять не собирались.

Значение по умолчанию подставляется значением при добавлении и плейсхолдером при правке. Разница смысловая: при создании умолчание — то, что отправится, если не трогать; при правке — то, что уже стоит, и подставлять его как значение значило бы отправлять его обратно.

`list` получает подпись «(comma-separated)» и плейсхолдер `a, b`. Некрасиво по сравнению с тегами-чипсами — и честно: пользователь видит формат, в котором поле будет разобрано.

## Шаг 3 — Список: наблюдаемое поверх настроенного

```js
async function loadUnits() {
  const d = await (await fetch(ROWS())).json();
  const byId = {};
  for (const c of d.configured || []) byId[c.id] = { ...c, phase: 'silent', worker_state: 'stale' };
  for (const r of d.rows || []) byId[r.id] = { ...byId[r.id], ...r };   // the heartbeat's word wins over the row's
```

Три строки, в которых лежит вся модель консоли.

Начинаем с **настроенного** — строк из хранилища (урок 11). Каждой сразу приписываем `phase: silent` и `worker_state: stale`: по умолчанию мы ничего о единице не наблюдаем.

Потом накладываем **наблюдаемое** — модель чтения из heartbeat'ов (урок 13). И комментарий договаривает правило: *слово heartbeat'а сильнее слова строки.* Строка говорит, что должно быть; heartbeat — что есть; на экране побеждает второе.

Отсюда три состояния, различимые с одного взгляда:

| Настроено | Наблюдается | Что видит оператор |
|---|---|---|
| да | да | обычная строка, точка по фазе |
| да | нет | `silent`, «unplaced», серая точка |
| нет | да | строка ещё есть, но её уже удалили; исчезнет на следующем проходе |

Третий случай — самый поучительный: удалённая единица, чей воркер ещё не дошёл до следующего цикла. Если бы страница брала только `rows`, оператор решил бы, что удаление не сработало.

```js
    li.className = `${c.phase || 'silent'} ${c.worker_state === 'stale' ? 'stale' : ''} ${current === c.id ? 'on' : ''}`;
    li.innerHTML = `<span><span class="dot"></span>${label(c)} <small>#${c.id}</small></span>` +
                   `<small>${c.worker ? c.worker + (c.server ? ' · ' + c.server : '') : 'unplaced'}${c.age != null ? ' · ' + c.age + ' s' : ''}</small>`;
```

Цвет точки — класс фазы, покрашенный в CSS: `running` зелёный, `failed` красный, всё прочее серое. `stale` приглушает всю строку.

Справа — воркер, сервер и возраст наблюдения в секундах. Возраст — самое полезное число на экране: он отвечает на вопрос «это правда сейчас или было правдой минуту назад» без интерпретации.

```js
  try { const m = await (await fetch('/metrics')).text(); const live = /_workers_live (\d+)/.exec(m); const run = new RegExp(`_${spec.metrics.running} (\\d+)`).exec(m);
        $('#status').textContent = `${live ? live[1] : '?'} workers live · ${run ? run[1] : '?'} ${spec.metrics.running.replace(/_/g, ' ')}`; } catch (_) {}
```

Страница разбирает **текст Prometheus регулярным выражением**. Приём грубый, и он здесь уместен: формат из урока 18 — две строки, имя метрики известно из `spec.metrics.running`, а отдельный JSON-маршрут ради двух чисел был бы третьим представлением тех же данных.

`catch (_) {}` без тела — сознательно: метрик нет, строка состояния пуста, список работает. Этот приём повторится в файле восемь раз, и правило у него одно: **украшение падает молча, основное — нет.**

## Шаг 4 — Таймлайн

```js
  const lo = window_ ? from : Math.min(...spans.map(s => s.start), ...events.map(e => e.t), now - 3600);
  const hi = window_ ? to : Math.max(...spans.map(s => s.end), ...events.map(e => e.t), now);
  const tl = $('#timeline'); tl.innerHTML = '';
  const x = t => 100 * (t - lo) / Math.max(1, hi - lo);
```

Видимый диапазон: заданное окно либо, если окна нет, от самого раннего из всего, что есть, до самого позднего. `now - 3600` и `now` в аргументах `Math.min`/`Math.max` — не «данные за час», а **гарантия непустого диапазона**: у единицы без записей и без событий таймлайн всё равно имеет ширину, и на нём видно «здесь ничего нет», а не пустоту неопределённого масштаба.

`x` — единственная математика на странице: время в проценты. Отсюда и всё остальное: элементы позиционируются в процентах, значит масштабируются вместе с окном браузера, и перерисовывать при ресайзе нечего.

```js
    el.className = `span ${s.media ? '' : 'events-only'} ${s.fenced ? 'fenced' : ''}`;
    el.style.left = x(s.start) + '%'; el.style.width = Math.max(0.2, x(s.end) - x(s.start)) + '%';
    el.title = `${fmt(s.start)} – ${fmt(s.end)} · epoch ${s.epoch}${s.fenced ? ' (fenced)' : ''}${s.server ? ' · ' + s.server : ''}${s.events ? ' · ' + s.events + ' events' : ''}${s.media ? '' : ' · not recorded'}`;
    if (s.media) el.onclick = () => play(i);
```

Три класса — три вида интервала, и два из них про смысл, а не про вид:

- обычный (`--media`, синий, высокий) — есть запись, кликается, играется;
- `events-only` (`--events`, янтарный, тонкий и ниже) — камера была под наблюдением, но не записывалась: события есть, играть нечего;
- `fenced` (прозрачность 0.45) — данные, чью эпоху перебила следующая (урок 6). Их видно, и видно, что им нельзя верить.

`Math.max(0.2, …)` — минимальная ширина в процентах: десятисекундный сегмент на суточном окне иначе не имел бы ни одного пикселя.

`title` вместо своей подсказки: браузерный тултип показывает всё, что известно об интервале, и стоит одну строку.

`onclick` вешается **только на интервалы с записью**. Клик по янтарному не делает ничего — и это лучше, чем клик, открывающий пустой плеер.

## Шаг 5 — События всех подсистем

```js
const PALETTE = ['#c58a1a', '#8e44ad', '#2a9d5c', '#d35400', '#16a085', '#7f8c8d'];
```

Цвет подсистемы назначается **в момент первой встречи**. Страница не знает и не может знать, какие подсистемы существуют: события приходят с ресурсов, ресурсы хранят бакеты любых подсистем (урок 16), и завтра появится пятая.

Цвет получается стабильным в пределах загрузки страницы и может поменяться после перезагрузки, если порядок первой встречи изменился. Цена за то, чтобы не заводить реестра подсистем ради палитры; легенда рядом с таймлайном снимает вопрос.

Поля события выводятся **вычитанием**: известные платформе показаны на своих местах, а всё остальное — как есть, `ключ=значение`. Список запрещённых имён — это ровно поля, которые платформа кладёт в каждое событие (урок 14).

```js

  const i = spans.findIndex(s => s.media && s.start <= t && t < s.end);
  if (i < 0) { $('#playing small').textContent = `${fmt(t)} · not recorded at that moment`; return; }

```

Клик по событию — переход к моменту. Ищется интервал **с записью**, содержащий `t`; не нашли — честная фраза «в этот момент не записывалось», а не тишина.

`loadedmetadata` с `{ once: true }` — потому что `currentTime` до загрузки метаданных ничего не делает. `once` обязателен: без него обработчик накопится по одному на каждый переход, и десятый клик перемотает видео десять раз.

## Шаг 6 — Записи и ключ на каждый клик

```js
const key = () => (crypto.randomUUID ? crypto.randomUUID() : String(Math.random()).slice(2));

async function send(method, path, body) {
  const r = await fetch(path, { method, headers: { 'Content-Type': 'application/json', 'Idempotency-Key': key() }, body: body === undefined ? undefined : JSON.stringify(body) });
  const text = await r.text();
  let d = {}; try { d = JSON.parse(text); } catch (_) {}
  if (!r.ok) throw new Error(d.detail || d.error || `${r.status}`);
  return d;
}
```

Одна функция на все записи, и в ней три вещи.

**Ключ на каждую попытку**, не на каждую форму. Оператор нажал «Add», не дождался, нажал ещё раз — это две попытки с двумя разными ключами, и будет две единицы. Ключ защищает от повтора **сети**, не от повтора **человека**; от второго защищает то, что кнопка отвечает быстро.

`await r.text()` до разбора: ответ может оказаться не JSON (прокси вернул HTML-страницу ошибки), и тогда `r.json()` выбросил бы синтаксическую ошибку вместо кода состояния.

`d.detail || d.error || status` — **слова сервера, не свои**. Страница нигде не сочиняет текст отказа. `refuse` из урока 10 уже написал человеческую фразу; переводить её в свой словарь значило бы потерять точность и завести второе место, где эту фразу надо менять.

```js
const fields = form => {
  const out = {};
  for (const f of spec.fields) {
    const el = form.elements[f.name]; if (!el) continue;
    if (f.type === 'bool') { out[f.name] = el.checked; continue; }
    const v = el.value;
    if (v === '') continue;                                              // unset: the spec's default on create, unchanged on edit
    out[f.name] = f.type === 'list' ? v.split(',').map(x => x.trim()).filter(Boolean)
                : f.type === 'int' ? parseInt(v, 10) : f.type === 'float' ? Number(v) : v;
  }
  return out;
};
```

Форма читается **по спецификации**, а не по DOM: цикл идёт по `spec.fields`, а не по `form.elements`. Следствие важнее удобства: поле, случайно попавшее в разметку, в тело запроса не попадёт. `worker`, `epoch`, `revision` не отправятся никогда — их нет в `spec.fields`, потому что консоль их не получает (урок 10).

Пустое значит «не задано». `bool` — исключение: галочка всегда имеет значение, и снятая галочка — это `false`, а не отсутствие.

## Шаг 7 — Плеер, живая картинка и живая лента

```js
function play(i) {
  queue = spans.map((s, j) => j).filter(j => j >= i && spans[j].media);
  next();
}
function next() {
  if (!queue.length) return;
  stopLive();
  const i = queue.shift(); const s = spans[i];
  [...$('#timeline').children].forEach((el, j) => el.classList.toggle('playing', j === i));

  const v = $('#player'); v.src = segmentURL(s); v.play().catch(() => {});
}
$('#player').onended = next;
```

Очередь индексов и переход по `onended`. **Один сегмент за раз, следующий — когда кончился предыдущий**, с видимым швом между ними.

Почему не бесшовно. Бесшовное воспроизведение фрагментированного MP4 делается через Media Source Extensions: буфер, склейка, обработка разрывов. Это несколько сотен строк на странице и нетривиальная отладка — и, главное, не та задача: склейка сегментов в непрерывный поток делается шлюзом в М12. Консоль показывает **то, что ресурс отдаёт**, и шов на границе сегментов честно сообщает, где кончилась одна запись и началась другая.

`v.play().catch(() => {})` — браузер отказывает в автовоспроизведении, пока не было клика по странице. Здесь клик всегда был, но отказ не должен ронять обработчик.

Подпись называет сервер: на кластере сегменты могут прийти с зеркала соседа (урок 16), и оператор должен видеть, откуда играет.

```js
async function startLive() {
  stopLive();
  const pc = new RTCPeerConnection();
  pc.addTransceiver('video', { direction: 'recvonly' });
  pc.ontrack = e => { const v = $('#player'); v.src = ''; v.srcObject = e.streams[0]; v.play().catch(() => {}); };
  await pc.setLocalDescription(await pc.createOffer());
  let r, tries = 0;
  for (;;) {
    r = await fetch(`/whep/${current}`, { method: 'POST', headers: { 'Content-Type': 'application/sdp' }, body: pc.localDescription.sdp });
    if (r.status !== 503 || ++tries > 8) break;
    $('#playing small').textContent = 'live: waiting for a gateway…';
    await new Promise(res => setTimeout(res, 1500));                    // the live controller's next pass
  }
```

Живая картинка идёт по WHEP: браузер делает предложение, консоль передаёт его шлюзу, шлюз отвечает. Сама подсистема живого вещания — в М10B; здесь важна **форма ожидания**.

`503` означает «ещё не размещено»: первый зритель создал единицу вещания, и контроллер разместит её на своём следующем проходе. Страница повторяет до восьми раз по полторы секунды — двенадцать секунд, заведомо больше цикла контроллера — и **пишет, чего ждёт**. Фраза «waiting for a gateway» превращает подвисший интерфейс в понятный процесс.

`recvonly` и отсутствие `getUserMedia`: страница только смотрит. Камеры и микрофона у неё не спрашивают никогда, и это видно по коду.

```js
async function pollLive() {
  if (!live) return;
  let d;
  try { const r = await fetch(`/events?from=${live.since}&to=1e12&cam=${encodeURIComponent(current)}`); if (!r.ok) return; d = await r.json(); } catch (_) { return; }
  const feed = $('#livefeed');
  for (const e of (d.events || []).sort((a, b) => a.t - b.t)) {
    const k = `${e.server}|${e.bucket}|${e.t}|${e.kind}`; if (live.seen.has(k)) continue; live.seen.add(k);
```

Живая лента — самая недооценённая часть страницы. Пока оператор смотрит картинку, рядом появляется то, что **наблюдают все подсистемы** на этой же единице: пересечение линии детектором, отметка другого оператора, `silent` от воркера.

Картинка приходит от шлюза, события — с ресурса, и **страница соединяет их только по времени**. Никакого общего канала, никакой синхронизации: два независимых потока рядом на экране, и человек сводит их сам.

Ключ дедупликации `server|bucket|t|kind` — потому что опрос перекрывается: `since` отодвигается на секунду назад от последнего увиденного, чтобы не потерять событие, записанное в ту же секунду. Перекрытие плюс множество увиденных — обычный приём хвостового чтения, и он дешевле, чем курсор.

Тридцать записей максимум: `while (feed.children.length > 31)` — тридцать событий плюс заголовок.

```js
function stopLive() {
  if (!live) return;
  fetch(live.session, { method: 'DELETE' }).catch(() => {});        // the viewer hangs up; the gateway drops the peer
```

Уход зрителя сообщается явным `DELETE`. Без него шлюз держал бы соединение до таймаута, а последний ушедший зритель не освободил бы единицу вещания. `window.addEventListener('beforeunload', stopLive)` в конце файла закрывает и случай закрытой вкладки.

## Шаг 8 — Ручка администратора и опрос

```js
const POLICY_HELP = { shared: 'every worker carries units, two on one server included; a dead server\'s worker is rescheduled onto a neighbour by the scheduler',
                      distinct: 'one worker per server carries units; a dead server\'s units are moved by the controller once its worker and its resource are both silent' };
```

Политика из урока 13 — выпадающий список из двух значений и **строка о том, что каждое означает**. Не «shared/distinct» без пояснения: выбор, последствия которого администратор не понимает, хуже отсутствия выбора.

Текст описывает не настройку, а поведение при отказе: кто подхватит единицы мёртвого сервера — планировщик или контроллер. Это то, ради чего ручку крутят.

```js
loadSpec().then(() => { loadUnits(); loadResources(); setInterval(() => { loadUnits(); loadDets(); loadRec(); loadResources(); }, 10000); setInterval(loadEvents, 5000); });
```

Последняя строка файла. Два таймера, и разные интервалы не случайны: состояние единиц и серверов обновляется раз в десять секунд, события — раз в пять, потому что событие — это то, ради чего смотрят, и задержка в нём заметнее.

Никаких веб-сокетов, никакого SSE. Опрос проще, переживает разрыв сети без кода переподключения и на десятке камер стоит два запроса в секунду. Если единиц станут тысячи — это первое место, где придётся передумать, и до тех пор менять его не за чем.

Одна и та же страница показывает:

| Подсистема | Что видно |
|---|---|
| `ticks` (урок 13) | список тиков, форма из двух полей, состояние воркеров. Ни таймлайна, ни плеера — `media: false` |

## Что может пойти не так

- **`if (spec.name === 'vms')` на странице.** Одна такая строка — и через полгода их двенадцать. Тест ищет слово *camera*; он не поймает `'vms'`. Ловить придётся на ревью.
- **Формы, построенные из DOM, а не из `spec.fields`.** Первое же скрытое поле уедет на сервер, и `refuse` вернёт отказ, причину которого будут искать в браузере.
- **`loadedmetadata` без `{ once: true }`.** Обработчики копятся, перемотка начинает прыгать после десятого клика, и связь с кликами не очевидна.
- **Своя формулировка отказа вместо `detail`.** Оператор читает «Ошибка сохранения», а сервер сказал «capacity 8 exceeded on worker w-2».
- **Один ключ идемпотентности на форму вместо ключа на попытку.** Исправленное значение уйдёт под старым ключом и получит в ответ старую строку — правка «не применится» без единой ошибки.
- **Молчаливое `state != live`.** Список событий короче правды и выглядит полным. Красьте.
- **Веб-сокет ради живой ленты.** Переподключение, состояние соединения, обратное давление — три новых источника багов ради экономии двух запросов в секунду.

## Итог

- Страница знает только `/spec`: имя, строки, поля, наличие медиа. Всё остальное она строит.
- Настроенное и наблюдаемое накладываются, и слово heartbeat'а сильнее слова строки — отсюда три различимых состояния единицы.
- Таймлайн — проценты и абсолютное позиционирование: масштабируется сам, библиотеки не требует.
- Цвет подсистемы назначается при первой встрече: реестра подсистем у страницы нет и быть не должно.
- Поля события выводятся вычитанием известных — новое поле появляется на экране в день, когда его начали писать.
- Ключ идемпотентности — на попытку; текст отказа — сервера; украшение падает молча, основное — нет.
- Архив играется сегментами со швами: склейка — задача шлюза в М12, а не страницы.
