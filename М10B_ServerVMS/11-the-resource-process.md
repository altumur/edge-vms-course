# Урок 11 — Процесс ресурса

**Модуль:** М10B — ServerVMS (часть вторая)
**Вы напишете:** `vms/resource.py` — `vms_routes` (`/manifest/<cam>` и `/segment/<path>` с диапазонными запросами) и `vms_resource` (платформенный `Resource` с политикой регистратора и базой событий); плюс `__main__.resource` — цикл процесса, у которого нет контроллера.
**Время:** ~70 минут.

## Зачем этот урок

Урок короткий, и короток он не потому, что в нём мало смысла, а потому, что **почти всё уже написано**.

Ресурс как понятие появился в уроке 1 М10A («то, что не может переехать»), как класс — в уроке 16 М10A (heartbeat, зеркало, хранение, регистрация чужих проходов, HTTP), как архив — в уроках 7–8 этого модуля. Здесь всё это соединяется в процесс, и VMS приносит **два маршрута и одну регистрацию**.

Шапка файла перечисляет, что от VMS:

```
ArchivePolicy   registered as the "rec" hook
vms_routes      GET /manifest/<cam>;  GET /segment/<path>, Range honoured
```

И тут же — что **не** от VMS:

```
Nothing about heartbeats, buckets, mirrors or the database is the VMS's, and
the names say so: platform/resources/<server>/heartbeat, platform/mirror.
```

**Имена ключей — доказательство границы.** `platform/resources/<server>/heartbeat`, а не `vms/resources/...`. Если бы ресурс был частью VMS, ключ назывался бы иначе, и подсистема детекторов в уроке 14 не смогла бы писать на тот же ресурс, не спросив разрешения.

Второй сюжет урока — **процесс без контроллера**. Обоснование было дано в уроке 16 М10A; здесь видно, как это выглядит в коде: цикл из двенадцати строк, в котором нет ни сверки, ни назначения, ни эпохи.

И третий — **диапазонные запросы**: тридцать строк, благодаря которым плеер на странице перематывает часовой сегмент, не скачивая его целиком.

> **Проверка без железа.** Весь урок. Маршруты проверяются настоящим HTTP на `port=0`, база событий — над временным каталогом.

## Что нужно знать заранее

- **М10A, урок 13** — `Resource`: heartbeat, `register`, `pass_`, `restore`, `serve`, `extra`.
- **М10A, урок 12** — `EventDatabase`: кэш над деревом, `rebuild`, `tail`, `forget`.
- **Уроки 7–8** — `Manifest`, `ArchivePolicy`, два дерева.
- **М10A, урок 14** — протокол `extra`: четыре формы ответа, включая байты с заголовками.

## Чему вы научитесь

1. Приносить подсистему на чужой процесс двумя функциями.
2. Отвечать на диапазонный запрос и понимать, что без этого не работает.
3. Запускать базу-кэш в правильном порядке относительно восстановления.
4. Писать цикл процесса, у которого нет ни контроллера, ни назначения.
5. Читать имена ключей как утверждение о принадлежности.

## Шаг 1 — Что ресурс делает и чего не делает

```
It has no controller: it has a policy pass on a timer, a heartbeat, its HTTP,
and the event database over its own tree.
```

Четыре вещи, и ни одной из них не нужен контроллер.

**Проход политики на таймере** — не решение, а правило (урок 16 М10A). Чинить манифесты и удалять просроченное надо всегда одинаково; решать тут нечего.

**Heartbeat** — ресурс рассказывает о себе: адрес, занятое место, какие подсистемы на нём лежат, какие зеркала он держит. По нему его находят контроллеры (`requires: resource`) и консоль.

**HTTP** — чтение. Единственный способ добраться до данных ресурса с другой машины.

**База событий** — кэш над собственным деревом.

Чего нет: размещения (ресурс там, где он есть), эпохи (у него нет конкурентов за его дерево), слота (он один на сервер и назван сервером), назначения (никто ему ничего не назначает).

## Шаг 2 — Манифест как строки

```python
def vms_routes(archive: ArchiveResource):
    """The VMS's reads on the resource, plugged into the platform's server."""
    root = archive.root

    def extra(path: str, headers):
        if path.startswith("/manifest/"):
            cam = int(path.rsplit("/", 1)[1])
            return 200, "".join(l for l in Manifest(root, cam)._lines()).encode()
```

Замыкание над корнем архива, возвращающее функцию `extra` — протокол из урока 18 М10A. Платформа не знает о ней ничего, кроме формы ответа.

`/manifest/<cam>` отдаёт **сырые строки файла**, не разобранный JSON. Обратите внимание на `_lines()` — приватный метод, отдающий текст как есть.

Почему не `read()` с перекодированием в JSON: строки уже JSON, каждая по отдельности. Разобрать и собрать обратно — работа без результата, а при большом манифесте ещё и память.

Кто это читает — консоль VMS в уроке 12, чтобы построить таймлайн. Она получает то же, что лежит на диске, и разбирает сама.

## Шаг 3 — Диапазонные запросы

```python
        if path.startswith("/segment/"):
            rel = path[len("/segment/"):]
            p = os.path.join(root, rel)
            if ".." in rel or not os.path.isfile(p):
                return 404, b""
```

Проверка `..` — та же защита от обхода каталога, что в уроке 5. Здесь она обязательна вдвойне: путь приходит из HTTP, то есть от кого угодно.

Проверка и отсутствия файла, и `..` дают **один и тот же ответ** — 404 с пустым телом. Не 403 для `..`: разные коды сообщили бы атакующему, существует ли путь.

```python
            size = os.path.getsize(p); start, end = 0, size - 1
            rng = headers.get("Range")
            if rng and rng.startswith("bytes="):
                a, b = rng[6:].split("-"); start = int(a or 0); end = int(b) if b else end
            with open(p, "rb") as f:
                f.seek(start); data = f.read(end - start + 1)
            return (206 if rng else 200), data, ((("Content-Range", f"bytes {start}-{end}/{size}"),) if rng else ())
```

Восемь строк, и без них плеер не работает.

**Что делает браузер с видеофайлом.** Он не скачивает его целиком. Он просит первые несколько килобайт, находит в них `moov` (таблицу смещений), и дальше **просит ровно те байты, которые нужны для запрошенного момента**. Перемотка на середину десятиминутного сегмента — это один запрос `Range: bytes=52428800-` вместо ста мегабайт.

Сервер без поддержки `Range` заставляет браузер качать весь файл до нужного места. На десятиминутном сегменте это ощутимо; на часовом — неприемлемо.

Разбор заголовка минимальный: `bytes=<a>-<b>`, обе части необязательны. `bytes=100-` — от сотого байта до конца. `bytes=-500` здесь разберётся неправильно (последние 500 байт по стандарту), и это **сознательное упрощение**: браузеры используют форму с явным началом.

`206 Partial Content` и `Content-Range` при наличии заголовка, `200` без него. Заголовок `Content-Range` обязателен: без него браузер считает частичный ответ полным файлом и получает битое видео.

Это единственное место в курсе, где используется четвёртая форма ответа `extra` — **байты со своими заголовками** (урок 18 М10A). Ветка `else` в `_extra`, которая тогда выглядела избыточной, существует ради этих восьми строк.

Чего здесь нет: `Accept-Ranges: bytes` в ответе на обычный запрос. Браузер и так пробует `Range` для видео; заголовок был бы вежливее, но не необходим.

## Шаг 4 — Сборка ресурса

```python
def vms_resource(archive: ArchiveResource, server: str, url: str, vars_, objects, wall=None, peers=None,
                 database: str = ":memory:") -> Resource:
    wall = wall or archive.wall
    r = Resource(archive.root, server, url, vars_, objects, archive.bucket_seconds, wall, peers)
    r.register("rec", ArchivePolicy(archive, vars_))                    # footage is the recorder's
    r.database = EventDatabase(archive.root, server, database, wall, archive.bucket_seconds)
    return r
```

Три строки, и каждая — соединение с тем, что написано раньше.

`Resource(...)` — платформенный класс из урока 16 М10A, ничего не знающий о видео.

`r.register("rec", ArchivePolicy(archive, vars_))` — **регистрация под именем подсистемы**. Имя `"rec"`, а не `"vms"`, и комментарий говорит почему: *видео принадлежит регистратору.* Дерево `vms/` на этом ресурсе содержит только события, и их убирает платформенный проход по строке `vms/retention/<cam>` (урок 1).

Дверь `register` (урок 16 М10A) была написана без единого знания о том, кто в неё войдёт. Вот первый вошедший. В уроке 14 войдёт второй — детекторы; в уроке 13 третий не понадобится, потому что живое видео ничего не хранит.

`r.database = EventDatabase(...)` — **присвоение атрибута, а не аргумент конструктора**. База создаётся, но не запускается: докстрока говорит *created; the process starts it after `restore()`*.

Почему это важно, видно в цикле процесса.

`database: str = ":memory:"` — по умолчанию база в памяти. Кэш, который пересобирается из дерева при каждом старте (урок 15 М10A); файл на диске — оптимизация для большого архива, включаемая переменной окружения.

## Шаг 5 — Цикл процесса

```python
def resource() -> None:
    """The resource process: the archive has no controller — it has a policy pass, a
    heartbeat, its HTTP, and the event database over its own tree."""
    archive = ArchiveResource(os.environ.get("SPOOL", "/data/spool"), os.environ.get("ARCHIVE", "/data/archive"))
    vars_ = FileVariables(os.path.join(root, "config"))
    objects = FsObjectStore(os.path.join(root, "objects"))
    host, port = os.environ.get("RESOURCE_HOST", "127.0.0.1"), int(os.environ.get("RESOURCE_PORT", "8090"))
    res = vms_resource(archive, socket.gethostname(), os.environ.get("RESOURCE_URL", f"http://{host}:{port}"), vars_, objects,
                       database=os.environ.get("EVENTDB", ":memory:"))
    srv = serve(res, host, port, extra=vms_routes(archive))
```

Имя ресурса — **имя хоста**. Не слот, не индекс: ресурс один на сервер, и сервер уже имеет имя. Взятие слота по CAS здесь было бы бессмысленным ритуалом.

`RESOURCE_URL` отдельно от `host:port` — потому что адрес, по которому ресурс доступен снаружи, может отличаться от того, на котором он слушает. В контейнере слушает `127.0.0.1:8090`, а снаружи известен как `http://box-a:8090`. Этот адрес попадает в heartbeat, и по нему консоль ходит за событиями.

```python
    res.heartbeat(); logging.info("restore: %s", res.restore())
    res.database.start()                                                  # a cache over THIS tree: rebuilt after restore, tailed every 3 s
```

**Порядок из трёх шагов, и он строгий.**

`heartbeat()` **первым**: заявить о себе до всякой работы. Восстановление может занять минуты (это копирование зеркал обратно после замены диска, урок 16 М10A), и всё это время контроллеры должны видеть, что ресурс есть. Иначе они успеют перераспределить записи с сервера, который на самом деле поднимается.

`restore()` **вторым**: забрать с соседей то, что было зазеркалено, пока этот сервер лежал. Комментарий говорит: *rebuilt after restore.*

`database.start()` **третьим**, и именно поэтому база создавалась, а не запускалась. Запусти её до восстановления — она проиндексирует дерево без вернувшихся бакетов, и до следующей пересборки события за время простоя были бы невидимы.

**Кэш строится после того, как данные на месте.** Простое правило, нарушение которого даёт ошибку, воспроизводящуюся только после аварии — то есть тогда, когда меньше всего хочется разбираться.

```python
    last_policy = 0.0
    while not stop.is_set():
        try:
            res.heartbeat()
            if time.time() - last_policy >= 600:
                logging.info("policy: %s", res.pass_()); last_policy = time.time()
        except Exception:                                                 # noqa: BLE001
            logging.exception("resource pass failed")
        stop.wait(10)
    res.database.stop(); srv.shutdown()
```

**Двенадцать строк — весь процесс.** Heartbeat каждые десять секунд, проход политики каждые десять минут.

Разница периодов: heartbeat дёшев и нужен часто (по нему решают, жив ли сервер, при `lost_after` в 45 секунд). Проход политики — обход каталогов и удаление файлов; чаще чем раз в десять минут незачем.

`pass_()` зовёт платформенный проход **и все зарегистрированные** (урок 16 М10A): свой — бакеты по срокам, `ArchivePolicy` — манифесты и видео. Результаты складываются в один словарь, попадают в журнал и в heartbeat.

Примечание к файлу сравнивает с тем, что было:

> *The old `vms-archive-retain.timer` ran the same policy as a oneshot every ten minutes; the process runs it every 600 s from its loop and adds what a oneshot could not hold: a heartbeat, a port, a database.*

**Тот же проход, та же периодичность.** Разница — в трёх вещах, которых у разовой задачи по таймеру быть не может: heartbeat (её не видно, пока она не запущена), порт (к ней нельзя обратиться) и база (ей негде жить между запусками).

`except Exception` и продолжение — та же логика, что в цикле воркера (урок 4): отказ одного прохода не должен ронять процесс.

`database.stop(); srv.shutdown()` на выходе. Слота нет — отпускать нечего, и различения «аккуратная остановка против падения» здесь тоже нет: ресурс никуда не переезжает, и контроллеру нечего решать по факту его ухода.

## Шаг 6 — Один процесс, две топологии

Последняя фраза примечания стоит отдельного абзаца:

> *М11 runs the same function as the `resource` job on every server (`cluster/resource.py` re-exports it), which is the point: the box and the cluster have one architecture.*

Тот же `vms_resource`, тот же цикл, тот же heartbeat. На коробке — один процесс под systemd; в кластере — системная задача Nomad на каждом сервере. **Не переписан ни один файл**; М11 только реэкспортирует функцию.

Это и есть проверка, ради которой ресурс в М10A писался как обобщённая работа платформы, а не как «архив VMS». Сущность, привязанная к серверу, ведёт себя одинаково независимо от того, сколько серверов.

## Что может пойти не так

- **Запустить базу до `restore`.** События за время простоя сервера окажутся невидимыми до следующей пересборки.
- **Heartbeat после восстановления.** Пока сервер поднимается, контроллеры сочтут его мёртвым и уведут с него записи.
- **Разбирать и пересобирать манифест в маршруте.** Работа без результата, и память на большом архиве.
- **Отдавать сегмент без `Range`.** Браузер скачает файл целиком до места перемотки.
- **`206` без `Content-Range`.** Браузер сочтёт кусок целым файлом и покажет битое видео.
- **Разные коды для `..` и отсутствующего файла.** Подскажете атакующему, что существует.
- **Регистрация политики под именем `vms`.** Платформенный проход по бакетам и проход регистратора начнут спорить за одно дерево.
- **Ресурс со слотом и эпохой.** Ритуал, ничего не защищающий: конкурентов за дерево сервера нет.
- **Проход политики каждые десять секунд.** Обход каталогов вместо работы.
- **Отдельный процесс для VMS-части ресурса.** Второй heartbeat, второй порт, второе размещение — при том что платформенный уже есть.

## Итог

- VMS приносит на ресурс две функции: маршруты и регистрацию политики. Всё остальное — платформенное, и имена ключей это утверждают.
- Ресурс не имеет контроллера: есть проход по таймеру, heartbeat, HTTP и база-кэш. Размещать нечего, отсекать некого.
- Порядок старта строгий: заявить о себе, восстановить, потом строить кэш. Кэш строится после того, как данные на месте.
- Диапазонные запросы — тридцать строк, без которых плеер качает сегмент целиком; `206` обязателен вместе с `Content-Range`.
- Имя ресурса — имя хоста; внешний адрес отделён от адреса прослушивания, потому что в контейнере они разные.
- Один и тот же процесс работает как юнит на коробке и как системная задача на каждом сервере кластера — М11 его только реэкспортирует.

## Упражнения

1. Запустите базу до `restore`. Уроните сервер на час, поднимите и спросите события за этот час.
2. Перенесите `heartbeat()` после `restore()`. Сделайте восстановление долгим (много зеркал) и посмотрите, что сделает контроллер записи.
3. Отдавайте сегмент без обработки `Range`. Перемотайте часовой сегмент на середину и замерьте трафик.
4. Верните `206` без `Content-Range`. Откройте сегмент в браузере.
5. Зарегистрируйте `ArchivePolicy` под именем `vms`. Опишите, что будут делать два прохода с деревом `vms/`.
6. Разбирайте манифест в JSON и собирайте обратно. Замерьте время ответа на манифесте в четыре тысячи строк.
7. Поставьте проход политики каждые десять секунд. Замерьте нагрузку на диск при сорока камерах.
8. Добавьте ресурсу слот и эпоху. Назовите, от чего именно они защищают.

## Что дальше

Ресурс отвечает, архив читается, события отдаются. Смотреть на это по-прежнему нечем: консоль из М10A ничего не знает ни о `/timeline`, ни о `/segment`, ни о живом видео.

> **Утверждение с оговоркой.** Здесь и в уроке 12 чтение архива не требует воркера: наш сегмент — файл на диске, у него нет ни состояния, ни ограниченной достижимости, ни потолка. Для архива, записанного **не нами** — на карте камеры или на NVR, — все три появляются, и [урок 15](15-the-archive-we-did-not-write.md) эту оговорку раскрывает.

[**Урок 12**](12-the-vms-console.md) пишет `vms/console.py`: маршруты `/timeline/<id>` и `/segment/<path>`, дверь WHEP, `LiveFront` — и дерево монтирования на четыре подсистемы, после которого страница из урока 19 М10A показывает VMS целиком.
