# Урок 12 — Консоль VMS

**Модуль:** М10B — ServerVMS (часть вторая)
**Вы напишете:** `vms/console.py` — `LiveFront` (дверь WHEP: `offer`, `where`, `hangup`, `status`), `vms_routes` (`/segment`, `/timeline`, `/whep`), `make_console` (дерево монтирования на четыре подсистемы) и `serve`.
**Время:** ~80 минут.

## Зачем этот урок

Страница из урока 19 М10A умеет всё: список, формы, таймлайн, плеер, живое видео, отметки. Она просит `/timeline/<id>`, `/segment/<path>`, `/whep/<cam>` — и до сих пор их никто не отдаёт.

Урок их отдаёт, и в шапке файла сказано, **сколько** для этого нужно:

> *Everything else — the page, /spec, /cameras, /where, /marks, /metrics, the POST/PUT/DELETE of a camera — is `w2cplatform.console.SpecConsole` reading `vms.subsystem.yaml`; nothing here knows what a camera's fields are.*

VMS добавляет к консоли **байты**: кусок видео из архива и таймлайн из манифеста. Плюс дверь в живое видео, которая сама медиа не носит.

Три вещи, ради которых урок стоит читать.

**`extra`, а не наследование.** Маршруты VMS **регистрируются** функцией (урок 18 М10A), а не добавляются подклассом `SpecConsole`. Разница принципиальная: подкласс знал бы о платформе изнутри, функция — только форму ответа.

**Консоль не носит медиа.** `LiveFront` создаёт единицу вещания, находит шлюз, передаёт ему предложение и **переписывает адрес сессии на себя**. Ответ называет шлюз, дальше RTP идёт шлюз → браузер, минуя консоль. Ни одного байта видео через неё.

**Дерево монтирования на четыре подсистемы.** `Mount` из урока 18 М10A получает своё применение: VMS на корне, `live`, `rec` и `det` — путями. Один процесс, один порт, одна страница.

> **Проверка без железа.** Весь урок: `test_the_console_over_http` проходит всю поверхность на настоящем порту — идемпотентный POST, отказ токену на размещении, диапазонный запрос сегмента, отметка в собственном бакете консоли.

## Что нужно знать заранее

- **М10A, уроки 17–19** — `SpecConsole`, `Mount`, `extra`, страница.
- **Урок 8** — `Manifest.timeline` и отсечённые интервалы.

Протокол из урока 18 М10A: `None` — не мой маршрут, `()` — я ответил сам, кортеж — ответ.

**Оба аргумента могут быть `None`.** `archive is None` — консоль на сервере без ресурса; `live is None` — живого видео нет. Тогда соответствующие маршруты просто не отвечают, и консоль возвращает 404.

Примечание называет конкретный случай: вторая консоль в тесте идемпотентности построена без архива. Так проверяется, что консоль без ресурса работает: создаёт камеры, показывает список, не отдаёт видео и отвечает 503 на отметку.

**Подсистема, которая не всё умеет, — это нормально**, и выражено это отсутствием маршрута, а не флагом.

```python

Тест проверяет буквально: `bytes=10-19` от 256-байтного сегмента даёт ровно эти байты и `Content-Range: bytes 10-19/256`.

## Шаг 2 — Дверь в живое видео

```python
class LiveFront:
    """The console's side of live video: the WHEP door. `POST /whep/<cam>`
    creates the fan-out unit `live/streams/<cam>` if nobody is watching yet
    (the console's token may write the operator's rows of the subsystem it
    fronts), finds which gateway the live controller placed it on, and
    proxies the offer there. Nothing here touches a worker, and the console
    never carries media: the answer names the gateway, and the browser's
    RTP goes gateway → browser from then on."""
```

Докстрока — это весь класс, изложенный заранее. Разберём по частям.

**«Создаёт единицу вещания, если ещё никто не смотрит».** Живое вещание — подсистема (урок 13), и её единица создаётся **не оператором**, а спросом. Первый зритель нажал «Live» — появилась строка `live/streams/<cam>`; последний ушёл — шлюз её удалит.

Это третий способ появления единицы в курсе: камеру создаёт оператор, запись создаёт оператор кнопкой, вещание создаёт **первый зритель**. Единица работы как след спроса, а не как настройка.

**«Консоль никогда не несёт медиа».** Через неё проходит только установление сессии: предложение туда, ответ обратно. Дальше браузер и шлюз говорят напрямую.

Представьте обратное: пятьдесят зрителей, чей RTP идёт через консоль. Консоль — один процесс на коробку, не размещаемый по ёмкости зрителей, не масштабируемый. Она стала бы узким местом мгновенно.

```python
    def where(self, cam: str) -> tuple[str | None, str | None]:
        pl = self.live.placement(cam)
        if not pl:
            return None, None
        hb = self.gateways().get(pl.worker)
        return pl.worker, (hb.extra.get("url") if hb else None)
```

**Два шага, и оба могут не сработать.** Размещение говорит, на каком шлюзе единица; heartbeat шлюза даёт его адрес.

Размещения нет — контроллер вещания ещё не прошёл. Heartbeat'а нет — шлюз размещён, но ещё не поднялся. Два разных состояния, и оба означают «подождите», а не «сломалось».

Адрес шлюза — снова **из heartbeat'а**, тем же способом, что регистратор искал камеру (урок 10). Один приём на всю систему.

## Шаг 3 — Предложение

```python
    def offer(self, cam: str, sdp: str, labels: list[str]):
        if self.ctl.camera(int(cam)) is None:
            return 404, {"error": f"no camera {cam}", "detail": f"no camera {cam}"}
```

Проверка существования камеры — **в подсистеме VMS**, до всего остального. Запрос вещания несуществующей камеры не должен создавать строку вещания.

```python
        if self.live.unit(cam) is None:
            try:
                self.live.create({"cam": str(cam), "labels": labels})
            except Refused as e:
                if "exists" not in str(e):
                    return 400, {"error": str(e), "detail": str(e)}
```

Создание по требованию, и **гонка обработана проглатыванием**.

Два зрителя нажали «Live» одновременно. Оба увидели, что единицы нет, оба зовут `create`. Один выигрывает CAS, второй получает `Refused("exists")` — и это **не ошибка**, а нормальный исход: единица есть, чего и добивались.

Проверка по подстроке `"exists"` груба. Альтернатива — отдельный класс исключения — потребовала бы правки платформы ради одного случая. Компромисс записан в коде и виден.

Любой другой `Refused` — настоящая ошибка (метки не прошли, поле не то), и он возвращается как 400.

```python
        g, url = self.where(cam)
        if not g or not url:
            return 503, {"error": "no gateway holds this stream yet — retry", "detail": "placed on the live controller's next pass", "retry_after": 2}
```

**`503` и объяснение.** Не 500 (мы ничего не сломали), не 404 (единица есть), не 202 (браузер не умеет ждать по нему).

Сообщение говорит **что произойдёт**: «разместится на следующем проходе контроллера вещания». `retry_after: 2` — сколько ждать.

Страница (урок 19 М10A) повторяет до восьми раз по полторы секунды и пишет «live: waiting for a gateway…». Двенадцать секунд на размещение, и всё это время пользователь видит процесс, а не зависший интерфейс.

**Ожидание размещения — штатное состояние распределённой системы.** Единицу создали секунду назад, контроллер ходит раз в несколько секунд. Система, отвечающая на это ошибкой, вынуждает нажимать «Live» дважды.

```python
        req = urllib.request.Request(f"{url}/whep/{cam}", data=sdp.encode(), method="POST", headers={"Content-Type": "application/sdp"})
        try:
            with urllib.request.urlopen(req, timeout=10) as r:
                data, status, loc = r.read(), r.status, r.headers.get("Location", "")
        except urllib.error.HTTPError as e:
            return e.code, {"error": f"gateway {g} said {e.code}", "detail": e.read().decode(errors="replace")}
        except OSError:
            return 503, {"error": f"gateway {g} is not answering — unavailable, not lost", "detail": g}
```

`urllib` из стандартной библиотеки — никаких зависимостей. Таймаут десять секунд.

**Два вида отказа, и формулировка второго стоит запомнить.**

`HTTPError` — шлюз ответил, и ответил отказом. Его код и его текст передаются как есть: виноват шлюз, и пусть он сам объяснится.

`OSError` — шлюз **не ответил**. Соединение отвергнуто, таймаут, сеть. И текст: *«шлюз не отвечает — недоступен, не потерян»*.

Различение, ради которого написана эта фраза: **недоступность не есть потеря**. Шлюз может перезагружаться, сеть может моргнуть. Ни единица вещания, ни её размещение от этого не исчезают. Консоль сообщает «сейчас нельзя», а не «этого нет», и ничего не удаляет.

Разница видна на следующем действии: если бы консоль сочла шлюз потерянным и удалила строку, зритель, повторивший через секунду, создал бы новую единицу, контроллер разместил бы её заново, и вместо паузы вышла бы перетасовка.

```python
        sid = loc.rsplit("/", 1)[-1]
        return status, data, [("Content-Type", "application/sdp"), ("Location", f"/whep/session/{sid}?gateway={g}")]
```

**Переписывание `Location`.** Шлюз вернул адрес сессии у себя; консоль подменяет его на свой, приписав имя шлюза параметром.

Зачем: браузер не должен знать адресов шлюзов. Он ходит на консоль, консоль знает куда переслать. Шлюзы могут быть в закрытом сегменте, их адреса — внутренние, их состав меняется.

`?gateway=<g>` — **состояние, вынесенное в URL**. Консоль не помнит, какая сессия на каком шлюзе: эта информация есть в адресе, который держит браузер. Перезапустили консоль — сессии живы, потому что помнить было нечего.

Тот же приём, что с идемпотентным ключом в хранилище (урок 17 М10A): **состояние не в памяти процесса.**

```python
    def hangup(self, sid: str, g: str):
        hb = self.gateways().get(g)
        if not hb or not hb.extra.get("url"):
            return 404, {"error": f"no gateway {g}"}
        req = urllib.request.Request(f"{hb.extra['url']}/whep/session/{sid}", method="DELETE")
```

Уход зрителя: имя шлюза из параметра, адрес из heartbeat'а, `DELETE` туда.

Без этого шлюз держал бы соединение до таймаута, и счётчик зрителей (по которому считается ёмкость, урок 13) врал бы.

## Шаг 4 — Дерево монтирования

```python
def make_console(ctl: VmsController, archive: ArchiveResource | None, wall=None, live_ctl: SpecController | None = None,
                 mounts: dict[str, SpecController] | None = None, index=None) -> Mount:
    """One console process for the box: the VMS at `/` (the page, /cameras, the media routes, the WHEP door),
    and every other subsystem the console fronts under its name — `/live/…`, `/det/…` — each a SpecConsole over
    that subsystem's spec with the console's token."""
    live = LiveFront(ctl, live_ctl) if live_ctl is not None else None
    index = index or MergedIndex(ctl.objects, wall=wall or time.time)   # no database here: the resource process's, asked over HTTP
    root = SpecConsole(ctl, marks_root=archive.root if archive else None, wall=wall, extra=vms_routes(archive, live), media=archive is not None, index=index)
    m = Mount(root)
    if live_ctl is not None:
        m.mount("live", SpecConsole(live_ctl, wall=wall, index=index))
    for name, c in (mounts or {}).items():
        m.mount(name, SpecConsole(c, wall=wall, index=index))            # every mount answers /events from the same merge
    return m
```

Двенадцать строк, собирающие всю консоль.

**VMS на корне**, остальные — путями. Оператор открывает `/` и видит камеры; `/rec/`, `/det/`, `/live/` — та же страница над другими спецификациями.

`media=archive is not None` — **`/spec` скажет `media: true` только при наличии архива**. Страница, прочитав это, нарисует таймлайн и плеер или не нарисует (урок 19 М10A). Одно поле в описании решает, как выглядит интерфейс.

`marks_root=archive.root if archive else None` — отметки оператора пишутся в собственный бакет консоли на ресурсе (урок 18 М10A). Нет ресурса — нет отметок, и `POST /marks` отвечает 503.

`index` — **один `MergedIndex` на все монтирования**, и комментарий объясняет: *no database here: the resource process's, asked over HTTP.*

У консоли нет базы событий. Она спрашивает ресурсы по HTTP и сливает ответы (урок 15 М10A). И индекс **общий для всех подсистем**: события камеры, детекторов и отметок приходят одним запросом, потому что лежат на одних ресурсах в разных деревьях.

Отсюда таймлайн, на котором рядом стоят засечки четырёх подсистем, — и ни одна из них об этом не знает.

Тест, который стоит прочитать целиком (он назван в примечании):

- идемпотентный POST даёт одну камеру;
- `VmsController` консоли **не может** `place` — токен;
- `PUT {"worker": "w-9"}` — 400;
- отметка попадает в `console/<unit>/e1/…`, и `subsystems_under(archive)` показывает **только `console`**, никогда `vms/1/`, у чьего бакета один писатель;
- страница не говорит «camera» нигде, кроме HTML-комментария.

Последние два — проверки границ, поставленные в М10A и здесь подтверждённые на настоящей подсистеме.

## Шаг 5 — Монтирования контейнера

Примечание к файлу заканчивается фразой, которая кажется административной и таковой не является:

> *The archive mount in `console.container` is what lets `/segment/` serve bytes; `/data/spool` is mounted read-only there because the console reads and never records.*

**Права на файловую систему повторяют права в хранилище.** Токен консоли не даёт писать размещение; монтирование контейнера не даёт писать в спул.

Один и тот же принцип, выраженный дважды разными механизмами. Ошибка в коде консоли не сможет испортить спул — не потому, что код правильный, а потому что файловая система смонтирована только на чтение.

Урок 15 разберёт все тринадцать юнитов и их монтирования; здесь достаточно заметить, что монтирование — часть проекта, а не деталь развёртывания.

## Что может пойти не так

- **Подкласс `SpecConsole` вместо `extra`.** Подсистема начнёт зависеть от внутренностей платформы, и следующая правка платформы сломает VMS.
- **Медиа через консоль.** Один нераспределяемый процесс на пути всего живого видео.
- **Адреса шлюзов в браузере.** Внутренние адреса наружу, и смена состава шлюзов ломает открытые вкладки.
- **Сессии в памяти консоли.** Перезапуск консоли обрывает всё живое видео.
- **`Refused("exists")` как ошибка.** Второй зритель, нажавший одновременно, получит отказ вместо картинки.
- **`404` или `500` вместо `503` при неразмещённой единице.** Пользователь нажмёт «Live» ещё раз вместо того, чтобы подождать две секунды.
- **Считать неотвечающий шлюз потерянным.** Моргнула сеть — единица удалена, размещена заново, перетасовка вместо паузы.
- **Своя база событий у консоли.** Второй индекс тех же данных, расходящийся с первым.
- **Разные `index` у монтирований.** Каждая подсистема будет видеть только свои события, и таймлайн распадётся.
- **Спул, смонтированный на запись.** Единственная защита от ошибки в коде консоли — снята.

## Итог

- VMS добавляет к консоли байты: `/segment` и `/timeline`. Всё остальное — платформа, читающая YAML.
- Маршруты регистрируются функцией, не наследованием: подсистема знает только форму ответа.
- Консоль не несёт медиа — только установление сессии; RTP идёт шлюз → браузер.
- Единица вещания создаётся первым зрителем: третий способ появления единицы в курсе.
- `503` с объяснением и `retry_after` — правильный ответ на «ещё не разместили»; недоступность не есть потеря.
- Состояние сессии вынесено в URL, а не в память консоли: перезапуск ничего не обрывает.
- `Mount` даёт один процесс, один порт и одну страницу на четыре подсистемы; общий `MergedIndex` сводит их события на один таймлайн.
- Права в хранилище и монтирования контейнера выражают одно и то же дважды.

## Упражнения

1. Сделайте маршруты VMS подклассом `SpecConsole`. Перечислите, на что теперь опирается подсистема.
2. Проведите RTP через консоль. Откройте пятьдесят вкладок и замерьте её загрузку.
3. Не переписывайте `Location`. Уберите один шлюз и посмотрите на открытые вкладки.
4. Храните соответствие «сессия → шлюз» в памяти консоли. Перезапустите её при трёх зрителях.
5. Считайте `Refused("exists")` ошибкой. Нажмите «Live» из двух вкладок одновременно.
6. Отвечайте 404 вместо 503 при неразмещённой единице. Опишите, что сделает страница из урока 19 М10A.
7. Удаляйте строку вещания при `OSError` от шлюза. Перезагрузите шлюз и опишите последовательность событий.
8. Дайте каждому монтированию свой `MergedIndex`. Откройте таймлайн камеры с детекторами.
9. Смонтируйте спул на запись. Назовите, какая ошибка в коде консоли теперь станет разрушительной.
