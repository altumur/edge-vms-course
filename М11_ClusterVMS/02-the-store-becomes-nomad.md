# Урок 2 — Хранилище становится Nomad

**Модуль:** М11 — ClusterVMS: воркеры, которые переживают свой сервер
**Вы напишете:** кластер Nomad из трёх серверов с включёнными ACL и raft на разделе данных; `cluster/variables.py` — контракт `Variables` из М10A поверх HTTP API Nomad, и `FakeVariables` — тот же контракт в памяти с теми же обещаниями; объекты как Variables под `objects/…`; и доказательство, что `vms/` смены хранилища не заметил.
**Время:** ~150 минут (60 без стенда).

## Зачем этот урок

Первое утверждение модуля: **в `vms/` ничего не меняется**, когда файлы становятся raft. Оба хранилища: и конфигурация, и — при таком размере — объекты. Всё, что будет дальше, стоит на этом утверждении, поэтому его нужно доказать первым делом, а не принять на веру.

Доказательство — не фраза «Nomad Variables похожи на наш каталог файлов». Доказательство — это список запросов, которые процесс кластера отправляет в Nomad, и два обещания, которые Nomad по ним даёт: `ModifyIndex`, растущий в одном журнале, и `PUT ?cas=`, который проходит, только если индекс не изменился. Если эти два обещания те же, что давали файлы на одной коробке, — код поверх них работает одинаково. Этот урок показывает запросы, обещания и то, как их держит фейк, на котором идут тесты. Заодно — как фейк их однажды нарушил и что это стоило бы.

> **Что проверяется без железа.** Всё, кроме самого кластера. `tests/test_lesson1_stores.py` гоняет базовые классы М10A поверх фейка кластера; `tests/test_trace.py` проверяет, что трасса, которую печатают уроки, — это ровно те запросы, которые отправляет настоящий `NomadVariables`: одни и те же операции идут через него к маленькому HTTP-серверу и через трассировщик, и запросы сравниваются. Полные трассы урока — в [`traces/`](traces/), файлы `02-*.txt`. Кластеру нужны три виртуальные машины со стенда М9 (или три чего угодно с ядром Linux и Podman).

## Что нужно знать заранее

- **Урок 1** — стенд модуля, первый воркер и его heartbeat.
- **М10A, урок 2** — `Variables`: `get`, `put(cas)`, `list`, `ModifyIndex`, `Conflict`.
- **М10A, урок 3** — `register_scheme`: хранилище — это URL.
- **М10A, урок 4** — `ObjectStore`.
- **М9, урок 4** — раздел данных `/data`, который переживает A/B-обновление. На нём будет жить raft.

## Чему вы научитесь

1. Поднять кластер Nomad из трёх серверов с ACL и raft на `/data`.
2. Прочитать четыре запроса к Nomad Variables и три кода ответа, на которых держится весь модуль.
3. Объяснить, почему `PUT ?cas=` — то же обещание, что давали файлы, и что именно оно гарантирует.
4. Показать, что объекты на этом кластере — тоже Variables, и чем за это платят.
5. Сказать, что обязан обещать фейк хранилища, и найти место, где он может соврать.

## Шаг 1 — Собрать кластер

Три машины со стенда М9 — `10.0.0.11`, `.12`, `.13` — у каждой раздел данных на `/data`. Их роли на стенде модуля — `srv-a`, `srv-b`, `srv-c` (урок 1).

**Ни `podman`, ни `exec2` в Nomad не встроены.** Оба — плагины в каталоге, который агенту нужно назвать:

```bash
mkdir -p /data/nomad/plugins
nomad version                                  # >= 1.8.0: блок disconnect (урок 8)
install -m 0755 nomad-driver-podman /data/nomad/plugins/
systemctl enable --now podman.socket
```

Конфигурация сервера — [`deploy/server.hcl`](clustervms/deploy/server.hcl):

```hcl
datacenter = "room-a"
data_dir   = "/data/nomad"

server {
  enabled          = true
  bootstrap_expect = 3
  server_join {
    retry_join = ["10.0.0.11", "10.0.0.12", "10.0.0.13"]
  }
}

acl {
  enabled = true
}
```

И клиента — [`deploy/client.hcl`](clustervms/deploy/client.hcl), на тех же трёх машинах:

```hcl
data_dir   = "/data/nomad"
plugin_dir = "/data/nomad/plugins"

client {
  enabled = true
  servers = ["10.0.0.11:4647", "10.0.0.12:4647", "10.0.0.13:4647"]
  meta {
    labels  = "vlan:cctv-a,vlan:cctv-b"   # какие сети видит этот сервер
    archive = "/data/archive"             # на этом сервере есть ресурс с дисками
  }
}
```

Три строчки здесь понадобятся позже, и каждая — решение, а не умолчание.

**`data_dir` на `/data`.** Здесь живёт raft — память кластера о каждой когда-либо выданной эпохе и каждом слоте. Обновление ОС на A/B-коробке меняет корневой раздел целиком; если raft там, после обновления сервер вернётся без памяти, и кластер разделится. Граница из урока 4 М9, применённая к планировщику.

**`meta.labels` и `meta.archive`.** Первое станет переменной `LABELS` воркера (урок 1) и ограничением размещения (урок 10). Второе — тем, что привязывает задание ресурса к этому серверу (урок 3). На стенде `labels` у каждого сервера свои: `vlan:cctv-a` у `srv-a`, обе сети у `srv-b`, `vlan:cctv-b` у `srv-c`.

**`acl { enabled = true }`.** Весь урок 5 стоит на том, что воркер не может записать строку камеры. Включать ACL позже, на работающем кластере, — это миграция. В первый день.

```bash
nomad server members         # три сервера, один лидер
nomad node status            # три клиента в ready; -verbose покажет драйвер podman здоровым
nomad acl bootstrap          # один раз; управляющий токен держите не в уроке
```

Вот и весь слой хранения кластера: raft и диски каждого сервера. Видео и события лежат на дисках серверов, как ресурсы (урок 6). Всё остальное — в raft.

## Шаг 2 — Четыре запроса

Контракт `Variables` из М10A — четыре метода. Над Nomad каждый — один HTTP-запрос ([`cluster/variables.py`](clustervms/cluster/variables.py), класс `NomadVariables`):

| Метод | Запрос | Ответ |
|---|---|---|
| `get(path)` | `GET /v1/var/<path>?namespace=default` | `200 {"Items": {...}, "ModifyIndex": N}` или `404` |
| `put(path, items, cas)` | `PUT /v1/var/<path>?namespace=default[&cas=N]` с телом `{"Items": {...}}` | `200 {"ModifyIndex": N}`, `409` при несовпадении, `403` без права |
| `list(prefix)` | `GET /v1/vars?prefix=<prefix>&namespace=default` | `200 [{"Path": ..., "ModifyIndex": ...}, ...]` |
| `delete(path, cas)` | `DELETE /v1/var/<path>?namespace=default[&cas=N]` | `200`, `409` |

Каждый запрос несёт заголовок `X-Nomad-Token` — токен того процесса, который его отправил. Откуда процесс его берёт и что токен разрешает — урок 5. Здесь важно одно: хранилище знает, **кто** пишет, и решает, можно ли, само.

Три кода ответа несут весь смысл, и на них стоит задержаться.

**`200` на `PUT` возвращает новый `ModifyIndex`.** Это номер записи в журнале raft. Он растёт на **весь кластер**, а не на ключ: запись в `vms/cameras/1` и запись в `vms/epoch/7` получают номера из одной последовательности.

**`409` — значит, кто-то успел раньше.** `PUT ?cas=1002` говорит: «запиши, если у ключа сейчас индекс 1002». Если с момента, когда я его прочитал, ключ кто-то изменил, индекс уже другой, и хранилище отказывает. `cas=0` — частный случай: «создай, только если ключа нет».

**`403` — значит, не твоё.** Процесс попробовал писать в префикс, который его токену не разрешён. Это не правило в коде процесса, а отказ хранилища (шаг 5).

## Шаг 3 — Консоль создаёт камеру

Трасса — [`traces/02-console-creates-a-camera.txt`](traces/02-console-creates-a-camera.txt). Консоль стенда создаёт камеру `north-gate` и делает шесть запросов.

Сначала номер. Камерам номера выдаёт счётчик `vms/next_id`, и выдаёт по CAS, как любую другую запись:

```
GET /v1/var/vms/next_id?namespace=default
→ 404

PUT /v1/var/vms/next_id?namespace=default&cas=0
{"Items": {"n": "1"}}
→ 200 {"Path": "vms/next_id", "ModifyIndex": 1001}
```

Счётчика ещё нет (`404`), поэтому консоль создаёт его со значением 1 и `cas=0`. Если в ту же секунду камеру создаёт вторая консоль, одна из них получит `409`, прочитает счётчик снова и возьмёт 2. Двух камер с одним номером не будет — и это решает хранилище, а не договорённость между консолями.

Потом сама строка — тоже с `cas=0`, чтобы не перезаписать камеру, если номер почему-то уже занят:

```
PUT /v1/var/vms/cameras/1?namespace=default&cas=0
```
```json
{
  "Items": {
    "id": "1",
    "revision": "1",
    "name": "north-gate",
    "source": "driverpack://acme/10.2.0.11",
    "enabled": "true",
    "events_retention_days": "365",
    "priority": "100",
    "labels": "vlan:cctv-a",
    "folders": "",
    "alarms": "",
    "ref": "",
    "cred_username": "",
    "cred_secret": "",
    "live": "always",
    "kind": "video"
  }
}
```
```
→ 200 {"Path": "vms/cameras/1", "ModifyIndex": 1002}
```

Все значения — строки. У Nomad Variables значения только строковые, поэтому `"enabled": "true"` и `"priority": "100"`, а список меток — строка через запятую. Типы восстанавливает спека подсистемы при чтении (`SPEC.row`, М10A урок 9): хранилище хранит текст, смысл знает подсистема.

Последняя пара запросов — срок хранения событий в отдельной строке `vms/retention/1`. Её читает ресурс (урок 6), которому незачем видеть всю строку камеры.

Полностью путь `POST /cameras` через консоль — с ключом идемпотентности и ответом, который найдёт повтор, — разобран в части 3 записок [`three-cameras`](../_notes-ru/three-cameras/03-creating-a-camera.md). Здесь мы смотрим на то, что под ним: на то, как запросы держатся на CAS.

## Шаг 4 — Два редактора одной строки

Самое важное обещание хранилища видно, только когда пишут двое. Трасса — [`traces/02-two-editors-one-row.txt`](traces/02-two-editors-one-row.txt): консоль A переименовывает камеру 1, консоль B одновременно меняет ей срок хранения. Обе читают строку с одним индексом:

```
# console A
GET /v1/var/vms/cameras/1?namespace=default
→ 200 {..., "ModifyIndex": 1002}

# console B
GET /v1/var/vms/cameras/1?namespace=default
→ 200 {..., "ModifyIndex": 1002}
```

B пишет первой — и проходит, потому что индекс ещё 1002:

```
# console B
PUT /v1/var/vms/cameras/1?namespace=default&cas=1002
{"Items": {..., "revision": "2", "events_retention_days": "30", ...}}
→ 200 {"Path": "vms/cameras/1", "ModifyIndex": 1004}
```

A пишет второй — со старым индексом, и получает отказ:

```
# console A
PUT /v1/var/vms/cameras/1?namespace=default&cas=1002
{"Items": {..., "revision": "1", "name": "north-gate-2", "events_retention_days": "365", ...}}
→ 409 {"ModifyIndex": 1004}
```

Посмотрите на тело этого `PUT`. В нём `events_retention_days: 365` — значение, которое A прочитала до того, как B его изменила. Без CAS этот запрос прошёл бы, и правка B исчезла бы молча: никто бы ничего не заметил, пока через месяц не стали бы искать, куда делись события. С CAS A получает `409`, читает строку снова и пишет поверх:

```
# console A
GET /v1/var/vms/cameras/1?namespace=default
→ 200 {..., "revision": "2", "events_retention_days": "30", ..., "ModifyIndex": 1004}

# console A
PUT /v1/var/vms/cameras/1?namespace=default&cas=1004
{"Items": {..., "revision": "2", "name": "north-gate-2", "events_retention_days": "30", ...}}
→ 200 {"Path": "vms/cameras/1", "ModifyIndex": 1006}
```

Обе правки на месте. Это делает `Controller.write` из М10A — примитив, которым пользуется каждая правка в платформе:

```python
def write(self, path: str, mutate, retries: int = 10) -> dict:
    for _ in range(retries):
        items, idx = self.vars.get(path)
        new = mutate(dict(items or {}))
        if new is None:
            return dict(items or {})     # менять нечего — ничего и не пишется
        try:
            self.vars.put(path, new, cas=idx)
            return new
        except Conflict:
            continue                     # кто-то успел раньше: прочитать заново и применить поверх
    raise RuntimeError(f"{path}: {retries} conflicts")
```

Прочитать, изменить, записать с индексом прочитанного; `409` — прочитать заново. Ровно так же работала запись на одной коробке, где индекс давал файл под блокировкой. Обещание то же — значит, и код тот же. Это и есть первое утверждение модуля, показанное запросами.

## Шаг 5 — Воркер пишет не туда

Трасса — [`traces/02-a-worker-may-not-write-a-camera.txt`](traces/02-a-worker-may-not-write-a-camera.txt), и она короткая:

```
# vmsworker (allocation 0 on srv-a)
PUT /v1/var/vms/cameras/1?namespace=default
{"Items": {"name": "mine now"}}
→ 403 "Permission denied"
```

Токен воркера разрешает писать его эпохи, его слот, его место и его heartbeat — и ничего больше. Строка камеры — не его. Отказ приходит от хранилища, а не из кода воркера: даже воркер с ошибкой, даже воркер, в который кто-то пролез, не может переписать конфигурацию. Какие префиксы разрешены какому процессу и как это проверяется изнутри аллокации — урок 5.

## Шаг 6 — Объекты — тоже Variables

Контракт `ObjectStore` из М10A — `put`, `get`, `list` байтов по ключу. На одной коробке это был каталог файлов. На кластере у него есть отдельная реализация для MinIO или S3 (`cluster/s3.py`) — но при размере серверной она не нужна. Объекты — это heartbeat'ы (около 10 КБ раз в 10 секунд от дюжины процессов) и срезы снимка. Для raft это не нагрузка. Второе хранилище со своим кворумом, своими учётными данными и своим клиентом — цена, которую коробке незачем платить.

Поэтому объект здесь — Variable под `objects/<ключ>` с одним полем `data` ([`cluster/objectstore.py`](clustervms/cluster/objectstore.py), `VariablesObjectStore`):

```python
    def put(self, key: str, data: bytes) -> None:
        check(key, len(data), self.max_bytes)
        self.vars.put(self._path(key), {"data": data.decode("utf-8")})    # без cas: побеждает последний heartbeat
```

Heartbeat воркера из урока 1 — это `PUT /v1/var/objects/vms/heartbeats/w-0` с JSON в поле `data`. ACL, пришедший с токеном воркера, покрывает его как любую другую Variable: воркеру разрешено писать `objects/vms/heartbeats/*`, но не срезы снимка, которые пишет контроллер.

За это платят потолком. **Одна Variable в Nomad — не больше 64 КиБ целиком**, со всеми ключами и значениями, и это не настройка, а константа в планировщике. Объект наследует этот потолок, и хранилище говорит о нём само: `VariablesObjectStore.max_bytes` — это 65 536 минус длина слова `data`, и запись сверх отказывается до того, как уйти по сети (М10A, урок 19). Снимок кластера из-за этого разрезан на части — по одной на воркера (урок 10). Когда кластер вырастет настолько, что heartbeat'ы станут нагрузкой для raft, `OBJECTS=s3+http://…` переключит объекты на MinIO теми же тремя вызовами — и `vms/` снова ничего не заметит.

## Шаг 7 — Что обязан обещать фейк

Тесты модуля идут не на Nomad, а на `FakeVariables` — том же контракте в памяти. Тесты проходят за миллисекунды, а `verify-bench.sh` проверяет те же обещания на настоящем кластере. Но фейку можно верить ровно настолько, насколько он держит **все** обещания Nomad. Их четыре:

1. `ModifyIndex` растёт в **одном журнале на весь кластер**;
2. `PUT ?cas=N` проходит, только если индекс ключа сейчас `N`, иначе — `409`;
3. `cas=0` создаёт только отсутствующий ключ;
4. запись вне разрешённых токену префиксов — `403`.

Первое фейк однажды нарушил, и это стоит разобрать, потому что именно такие ошибки не видны. У `FakeVariables` есть `as_writer(writer, allowed)` — тот же фейк, увиденный через токен другого процесса. Сделано это копированием атрибутов объекта. Словарь записей при копировании остаётся общим, а счётчик индексов был **числом** — и у каждой копии становился своим. Консоль и воркер писали в один словарь, но нумеровали записи каждый по-своему:

```
консоль:  PUT vms/cameras/1 → ModifyIndex 1001
воркер:   PUT vms/epoch/1   → ModifyIndex 1001      ← тот же номер
```

Чем это опасно? CAS сравнивает индекс, который процесс прочитал, с индексом ключа сейчас. Если два разных изменения могут получить один номер, то процесс с устаревшим индексом однажды попадёт на совпадение — и его запись пройдёт поверх чужой, без `409`. Ровно та потерянная правка, от которой защищает шаг 4, — и фейк бы её пропустил, а Nomad нет.

Нашёл это стенд урока: в трассе с двумя редакторами после записи консоли B индекс оказался меньше, чем был до неё. Исправление — счётчик в общем списке, который копия разделяет, а не дублирует:

```python
        # ОДИН журнал на весь кластер, общий для всех видов через токены: `as_writer` копирует атрибуты
        # этого объекта, а скопированное число — это второй счётчик.
        self._log = [1000]
```

И тест, который держит это обещание дальше, — `test_every_writer_sees_one_log`: консоль, воркер и снова консоль получают три разных растущих индекса.

Урок отсюда общий: **фейк проверяют против обещаний настоящего хранилища, а не против того, что тесты проходят.** С этой ошибкой все тесты модуля были зелёными.

## Шаг 8 — Ничего больше не изменилось

Последнее — сами базовые классы М10A поверх хранилищ кластера, без единой правки:

```python
sub = Subsystem("thing")
ctl = Controller(sub, c.vars, c.objects)                # базовые классы М10A, нетронутые
w = Worker(sub, None, c.vars, c.objects, instance="A")
w.claim_slot()                                          # -> "w-1"
w.heartbeat([{"id": 1, "phase": "running"}], server="srv-a")
ctl.workers_seen()                                      # -> {"w-1": ...}
ctl.assign("w-1", ["1"]); w.assignment().units          # -> ["1"]
w.take_epoch("1")                                       # -> 1
```

`test_m10s_base_classes_run_on_the_cluster_stores_unchanged` — имя и есть утверждение. А четыре потока через `next_epoch` на фейке выдают номера `1..200` без единого повтора (`test_the_epoch_issuer_under_four_threads_on_the_raft_fake`): это и значит CAS по `ModifyIndex`, откуда бы индекс ни брался — из блокировки файла или из журнала raft.

Хранилище выбирается одной строкой окружения: `CONFIG_URL=nomad://127.0.0.1:4646`. Схема `nomad://` регистрирует себя при импорте — `register_scheme("nomad", _open_nomad)` в конце `cluster/variables.py` (М10A, урок 3). Этот файл — 171 строка — единственное место модуля, которое знает, что Nomad существует.

## Результат

- Кластер из трёх серверов: `nomad server members` показывает трёх с одним лидером, ACL включены, raft на `/data`.
- `tests/test_lesson1_stores.py` и `tests/test_trace.py` зелёные: базовые классы М10A работают на хранилищах кластера, а трассы уроков — это запросы настоящего `NomadVariables`.
- Три трассы этого урока в `traces/`, и вы можете прочитать каждый запрос в них и сказать, какое обещание он проверяет.

## Что может пойти не так

- **`data_dir` на корневом разделе.** После A/B-обновления сервер возвращается без памяти, кластер разделяется.
- **ACL «потом».** На работающем кластере это миграция, а весь урок 5 стоит на том, что воркер не может писать чужое.
- **Прочитать один раз и писать много раз с первым индексом.** Каждая запись после первой — `409`. Пишите через `Controller.write`: он перечитывает.
- **Писать без `cas`, где он нужен.** Две консоли — одна потерянная правка, без единой ошибки.
- **Хранить в Variable то, что растёт.** Потолок 64 КиБ на всю Variable; снимок кластера поэтому разрезан по воркерам.
- **Верить фейку, потому что тесты зелёные.** Проверьте его против обещаний Nomad — иначе он пропустит ровно ту ошибку, от которой должен защищать.
- **Heartbeat отвечает `403`.** В политике воркера нет `objects/vms/heartbeats/*`: объекты здесь — Variables, и ACL на них действует.

## Итог

- Кластер — три сервера, raft на `/data`, ACL с первого дня.
- Контракт `Variables` — четыре запроса к Nomad; смысл несут `200` с новым `ModifyIndex`, `409` и `403`.
- `ModifyIndex` — номер в одном журнале на весь кластер; `PUT ?cas=` проходит, только если ключ не менялся с чтения.
- Две правки одной строки не теряются: `409`, перечитать, записать поверх — то же, что делали файлы на одной коробке.
- Объекты на этом кластере — Variables под `objects/…`; за это платят потолком 64 КиБ, о котором хранилище говорит само.
- Фейк хранилища обязан держать все обещания Nomad; тот, что нумеровал записи по-своему в каждом виде, пропустил бы потерянную правку.
- `vms/` смены хранилища не заметил: хранилище — это URL, а про Nomad знает один файл.

## Упражнения

1. Уберите из `Controller.write` повтор после `409` и прогоните сцену `two_editors_one_row`. Чья правка выжила?
2. Верните в `FakeVariables` счётчик-число и напишите сценарий, в котором устаревший CAS совпадает с чужой записью и проходит.
3. Посчитайте, сколько камер влезет в один срез снимка при потолке 64 КиБ, если строка камеры в снимке занимает 400 байт. Сравните с `CAPACITY` из урока 1.
4. Запустите четыре потока `next_epoch` на фейке с убранной блокировкой. Найдите первый повтор и объясните, почему настоящий raft его выдать не может.
5. Напишите политику ACL, которая даёт консоли только чтение `vms/*`, и скажите, чего она не должна видеть.
