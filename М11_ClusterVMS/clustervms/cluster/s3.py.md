# s3.py — an S3/MinIO object store with Signature Version 4, standard library only

**Role in the module.** The object-store adapter for a cluster that has outgrown Variables-as-objects or is rented (М12 Lesson 8): the same `put`/`get`/`list` as `objectstore.py`, against MinIO or S3 with path-style addressing. The docstring's reasons: the appliance image carries no boto3 (Lesson 2 keeps the image small), and the restore point only needs two verbs, so SigV4 is written out by hand for PUT and GET with the payload hash in the request. Correctness is pinned to Amazon's own worked examples ("Example: GET Object", bucket `examplebucket`, key `test.txt`, 24 May 2013, and the PUT example on the same page), which publish the expected signatures; `tests/test_s3.py` reproduces both byte for byte. Used only through `objectstore.open_store("s3+http(s)://…")`.

## Functions

### `_sha256(b) -> str`
Hex SHA-256 — used for the payload hash and the canonical request hash.

### `_hmac(key, msg) -> bytes`
HMAC-SHA256 digest — the key-derivation chain.

### `sign(method, host, path, query, headers, payload, access_key, secret_key, region, now, service="s3") -> dict`
Returns the full header dict to send, `authorization` included. The caller passes the headers it wants signed (e.g. `Range`); `host`, `x-amz-date` (`YYYYMMDDTHHMMSSZ`) and `x-amz-content-sha256` (the payload hash — S3 requires it for a signed payload) are added here. Steps, as SigV4 specifies:
- canonical headers: lower-cased names, trimmed values, sorted; `SignedHeaders` is the sorted names joined with `;`;
- canonical query: the `&`-separated pairs sorted (the caller pre-encodes values);
- canonical request: method, the URI-encoded path (`quote(path, safe="/~")` — so `$` in the PUT example's key is encoded), canonical query, canonical headers, signed headers, payload hash;
- scope `date/region/service/aws4_request`; string to sign `AWS4-HMAC-SHA256`, amz date, scope, hash of the canonical request;
- signing key: HMAC chain `"AWS4"+secret → date → region → service → "aws4_request"`;
- `Authorization: AWS4-HMAC-SHA256 Credential=<key>/<scope>, SignedHeaders=…, Signature=<hex>`.
`now` is injected so the tests can fix 2013-05-24.

## `class S3ObjectStore`
Path-style `<endpoint>/<bucket>/<key>`. Credentials from the constructor or `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`, which on a server come from a Variable through a Nomad `template` into the task's environment — never a file in the image.

### `__init__(self, endpoint, bucket, region="us-east-1", access_key=None, secret_key=None, timeout=10.0)`
Splits the endpoint into scheme and host; missing credentials raise `KeyError` from the environment lookup at construction, not at first use.

### `_request(self, method, key, payload=b"", query="")`
Signs `method /<bucket>/<key>` with the current UTC time and an empty extra-header set, builds the `urllib` request (body only for PUT), copies every signed header except `host` (urllib sets it), and returns the open response.

### `put(self, key, data)`
`PUT`; anything but 200/201/204 is an `IOError`.

### `get(self, key) -> bytes | None`
`GET`; 404 → `None`, other HTTP errors propagate.

### `list(self, prefix) -> list[str]`
`ListObjectsV2` (`?list-type=2&prefix=<url-encoded>`), **one page only** — the docstring: the heartbeat prefix holds one object per worker and a thousand is a page. Keys are pulled from the XML with a regex on `<Key>…</Key>`; the response has no nesting worth a parser. Sorted.

## Notes
- The canonical query is built from the raw `query` string, so a caller that passes unencoded characters would produce a signature S3 rejects; `list` is the only caller and encodes its prefix.
- `list` returns full keys as S3 has them (no bucket prefix to strip), so `open_store("s3+http://host/bucket")` gives `objects.list("vms/")` the same shape as the other adapters.
