# Слой вместо Nomad внутри воркера

Предложение к курсу и к продукту. Курс сейчас прячет склад за питоновский `Protocol`. Запуск процессов уже снаружи (Quadlet / job). Склад — нет: в кластере в процесс вшивают `NomadVariables()`. Если цель — k8s или другой оркестратор «небольшими провайдерами», контракт склада должен быть таким же внешним, как jobspec.

Одна фраза:

> Два адаптера, не один бог. Runtime поднимает процесс. Config — HTTP KV с CAS. Objects — blob без CAS. Воркер, контроллер, эпоха и диск не знают Nomad. Failover записи — не провайдер: слот, эпоха, архив не едет. Оркестратор только решает, когда и где поднять замену, и это тоже надо явно настроить.

Это не то, что написано в М10/М11. Исходники курса не меняются этим текстом. Здесь — как выровнять швы, если подменять оркестратор.

## 1. Что уже абстрагировано, а что нет

Nomad в курсе делает **две** работы. Их смешивают.

| Работа | Сейчас | Можно сменить без воркера? |
|---|---|---|
| **Runtime** — сколько процессов, на каком сервере | Quadlet `vmsworker@w-1` / Nomad `job count = N` | да: другой манифест |
| **Config** — желание: камеры, assignment, эпохи, слоты | `self.vars.get("vms/workers/w-0")` | сам воркер — да; **сборка** — нет: `NomadVariables()` в `__main__` у всех четырёх ролей (и в Go — свой клиент) |
| **Objects** — heartbeat, snapshot | `put/get/list`, без CAS | **в кластере** уже URL (`OBJECTS=`); на ящике — класс `FsObjectStore(…/objects)`, как Config |

`worker.py` не вызывает `nomad job` и не импортирует Nomad. Менять бэкенд KV, не трогая петлю, уже можно: подставить другой объект в `__main__.py`. Жёсткость в другом.

В кластере **все четыре** роли (`worker`, `controller`, `console`, `resource`) делают одно и то же: `NomadVariables()`. То же в [`clustervms-go`](./М11_ClusterVMS/clustervms-go/cluster/variables.go) и в М12 (`NomadVariables(addr=…)`). Objects в кластере уже выбирают по URL (`open_store(OBJECTS)`). Config — нет: класс зашит. На ящике оба склада — классы в `vms/__main__.py`, без URL.

Протечка имён — в самом `vms/worker.py` (ящик и кластер общие): `NOMAD_ALLOC_INDEX`, `NOMAD_NODE_NAME`, `NOMAD_ALLOC_ID`, `NOMAD_META_labels`. На ящике слот уже нейтральный (`WORKER_NAME=%i`); в кластере тот же код собирает `w-` + индекс. `NOMAD_TOKEN` читает клиент `NomadVariables()`, не петля. Runtime должен отдавать `WORKER_NAME` / `SLOT_INDEX` и имя сервера, не заставляя код знать Nomad.

Итого сейчас: смена KV = новый класс + правка `__main__` (и копии на Go / М12). Смена Objects в кластере = другой `OBJECTS=`. Смена Runtime = другой манифест. Предложение выровнять Config с тем, что Objects уже умеют в М11: клиент видит URL, не имя вендора.

`Variables` в [`variables.py`](М10_ServerVMS/vmsserver/psimplatform/variables.py):

```python
class Variables(Protocol):
    def get(self, path: str) -> tuple[dict | None, int]: ...
    def put(self, path: str, items: dict, cas: int | None = None) -> int: ...
    def list(self, prefix: str) -> list[str]: ...
```

Это интерфейс **для другого модуля на том же языке**. Тесты и М10→М11 на Python от этого выигрывают. Сменить язык воркера, вынести склад в отдельный сервис, подставить k8s без нового клиента — нельзя. Протокол компилятор не проверяет на проводе.

Запуск уже «спека снаружи». Склад — «класс внутри». Предложение: выровнять.

## 2. Предложение: три маленьких контракта

Не один слой «платформа». Три, с разными обещаниями.

```
                    ┌─────────────┐
   оператор / UI ──►│  консоль    │── пишет желание ──┐
                    └─────────────┘                   │
                    ┌─────────────┐                   ▼
   каждые ~5 с  ──►│ контроллер  │── CAS assignment ──►  Config HTTP
                    └─────────────┘                   │   GET/PUT ?cas=
                    ┌─────────────┐                   │
   каждые ~2 с  ──►│   воркер    │◄─ читает желание ──┘
                    │             │── CAS epoch/slot ──►  Config
                    │             │── heartbeat ───────►  Objects
                    │             │── mp4 / jsonl ─────►  диск resource
                    └─────────────┘
                    ┌─────────────┐
   systemd/Nomad/k8s│  Runtime    │── только процесс, count, node
                    └─────────────┘
```

### Config — HTTP KV с CAS

Единственное, что видят воркер, контроллер, консоль и resource: URL + токен. Не только воркер: иначе три роли останутся на `NomadVariables()`.

```
GET  /v1/var/vms/workers/w-0
PUT  /v1/var/vms/workers/w-0?cas=8123     тело: { "Items": { … } }
GET  /v1/vars?prefix=vms/cameras/
```

Семантика как у Nomad Variables (можно скопировать имена, чтобы бэкенд Nomad был прокси):

- ключ = путь, значение = маленький набор строк;
- `ModifyIndex` / `cas`: 200 записали, **409** — перечитай и повтори, **403** — этот токен сюда не пишет, **404** на GET — ключа нет `(пусто, cas=0)`;
- ACL по префиксу: воркер пишет `vms/epoch/*` и `vms/slots/*`, читает `vms/*`; консоль пишет камеры; контроллер пишет placement и assignment.

**KV** — не SQL: нет `SELECT WHERE`, нет join. Открыл ключ, прочитал или заменил целиком.

**CAS** — не замок. «Запиши, только если индекс всё ещё тот». Два контроллера не затирают списки камер.

За этим HTTP — провайдеры, воркер их не импортирует:

| Провайдер Config | Куда реально кладут |
|---|---|
| `file` | `/data/platform/config/vars/…` (сегодняшний `FileVariables`: корень `$PLATFORM_DIR/config`, ключ — имя файла с `/` → `%2F`) |
| `nomad` | прокси на `GET/PUT /v1/var` Nomad |
| `etcd` / свой raft | свой KV |
| тесты | память (`FakeVariables`) |

### Objects — HTTP или SDK, без CAS

Сейчас в Objects только то, что курс туда кладёт: heartbeat воркера и resource, snapshot. Целиком, последний победил, важен `ts`. Провайдеры уже есть: каталог, Variables под `objects/…`, S3/MinIO.

Толстые 30 полей камеры сюда **ещё не кладут** (в М10 вся строка в Variable). Это из главы 9 [`АРХИТЕКТУРА.md`](./АРХИТЕКТУРА.md), не из кода. Если выносить жир — он живёт здесь, с тем же `revision`, что тонкая строка в Config. Не смешивать heartbeat с CAS: иначе на каждую десятую секунду — конфликт и retry зря.

### Runtime — манифесты оркестратора

Не API внутри воркера. Спеки снаружи:

| Провайдер Runtime | Что делает |
|---|---|
| Quadlet | `vmsworker@w-1`, `Restart=always` |
| Nomad | `count = N`, constraint, `disconnect`, autoscaler |
| k8s | Deployment/StatefulSet, DaemonSet на resource, HPA по `assigned/capacity` |

Воркер получает только: слот (`WORKER_NAME`), имя сервера, labels, токен Config, `CAPACITY`, пути дисков.

## 3. Чего в слой не класть

Иначе получится второй Nomad, и k8s снова размажется по всему.

| Не здесь | Где живёт |
|---|---|
| `place()`, ёмкость, VLAN | контроллер поверх Config |
| пайплайны, эпоха в пути, jsonl | воркер + resource |
| «запусти 2 реплики» | Runtime |
| видео | диски сервера |
| `/place-camera`, `/start-pipeline` | нет таких URL |

Слой Config = `get` / `put(cas)` / `list`. Всё.

## 4. Как выглядит смена оркестратора

Пишете провайдеры, не воркер.

1. Config: бэкенд k8s (etcd / ваш сервис) с теми же URL.
2. Runtime: манифесты Deployment + DaemonSet; в под — `WORKER_NAME` или ordinal → слот; **слот всё равно забирают CAS’ом** (не верьте имени пода).
3. Objects: тот же S3 или новый bucket.
4. Политика смерти узла: аналоги `lost_after=45s`, `stop_on_client_after=25s`, `kill_timeout=20s`. Это не три строки YAML «как Nomad из коробки». Без них два писателя или дыра.

Ящик без кластера: Config `file` или тот же HTTP на 127.0.0.1 над файлами. Иначе Quadlet тащит «API ради API» — минус, см. ниже.

## 5. Failover: что общее, что нет

Формула «простой стенд и зал отличаются только провайдерами» верна для **проводов**. Для **записи** — нет.

Общее (остаётся в VMS при любом Runtime):

- камеры висят на слоте `w-0`, не на PID и не на hostname;
- новый писатель берёт эпоху CAS’ом, файлы в `…/e7/…`;
- контроллер не раздаёт камеры при краше, только при `released: true`;
- resource не едет: ролики мёртвого сервера недоступны, не потеряны.

Разное:

| | Ящик (file + systemd) | Кластер |
|---|---|---|
| Упал процесс | тот же диск, тот же слот, следующая эпоха | то же, если рестарт на той же ноде |
| Упал сервер | продукта нет: одна коробка | Runtime поднимает `w-0` на другом сервере; прошлое на старом диске |
| Кто считает узел мёртвым | systemd не умеет «подожди 45 с и поставь на соседа» | Nomad `disconnect` / k8s надо **задать**; дефолт k8s часто другой |

Итого: провайдеры меняют, *куда ходить за строкой* и *кто запускает PID*. Не меняют физику диска и забор эпохи. `K8sRuntime` сам не даёт урок М11 Lesson 4.

## 6. Плюсы

**Один код воркера и контроллера.** Python сегодня, Go завтра — оба клиенты одного HTTP. Смена языка не ломает склад.

**Оркестратор сменный.** Nomad BUSL, k8s, «только systemd на площадке» — манифесты и один бэкенд Config, не развилка в `place()`.

**Граница продукта явная.** Сейчас контракт — чужой (`/v1/var` Nomad) плюс питоновский класс. Свой URL: вы владеете 409/403 и ACL. Nomad становится одним бэкендом, как файл.

**Тесты.** Fake за HTTP или in-process клиент к памяти — тот же контракт, что у зала. Курс уже гоняет `FakeVariables`; сеть добавляет «клиент как в проде».

**Толстые настройки (если выносить).** Тонкая строка в Config, жир в Objects, один `revision`. В коде курса жир ещё в Variable; слой этому не мешает и не требует.

**Симметрия с запуском.** Студент видит одно правило: процесс не знает, кто его поднял; процесс не знает, какой KV сзади. Сейчас второе правило врёт в `__main__.py`.

**Меньше соблазна «камера = под».** Runtime не видит id камер. Config не видит поды. Это то же разделение, что `count` vs `vms/workers/w-0`.

## 7. Минусы

**Лишний hop и лишний процесс.** Сейчас воркер на ноде бьёт в локальный Nomad agent → raft. Ваш Config-сервис: ещё один бинарник, ещё одна сеть, ещё один отказ. Упал Config — нет новых правк и новых эпох; уже запущенное пишет (это уже закон курса). Цена: оперировать сервис, который *должен* переживать одну ноду не хуже raft.

**На одном ящике избыточен.** М10 прав: файлы с `ModifyIndex` без HTTP. Обязательный Config-демон на appliance — то, за что курс ругал лишний кворум. Компромисс: на ящике клиент `file://`, в кластере `http://config`. Два транспорта у клиента — снова «почти Protocol». Или всегда HTTP, на ящике слушает 127.0.0.1 над файлами — простота контракта ценой демона.

**Вы пишете второй Nomad Variables, если эмулировать 1-в-1.** Namespace, 64 KiB, blocking query, lock ID — не надо. Хватит CAS, list, ACL. Иначе слой толще, чем провайдер.

**Failover оркестратора всё равно разный.** k8s не подставится тремя файлами. Нужны StatefulSet vs Deployment (имя слота), anti-affinity к диску, поведение при `NotReady`, grace period под lease. «Небольшой провайдер» для Runtime — манифесты + сверка цифр с TTL эпохи. Это работа, её нельзя спрятать в KV.

**Двойной ACL.** Nomad workload identity сегодня режет Variables. Свой HTTP — свои токены, ротация, как коробка без Nomad получает токен. Доменный PKI курса это умеет, но это отдельный кусок, не «маленький провайдер».

**Задержка правки.** Опрос каждые 2 с никуда не денется, пока клиент сам не делает watch. Nomad Variables в курсе **poll** (`get` assignment + `get` каждой своей камеры), не blocking query (хотя у Nomad `?index=&wait=` есть). Свой HTTP *может* добавить watch — плюс сложность, минус нагрузка. На 200 воркерах при `CAPACITY=50` это тысячи GET/с, не «один раз при старте». Вынести Config с кворума Nomad на слабый одиночный сервис — станет хуже, не лучше.

**Heartbeat через тот же KV.** Если Objects = «Variables под `objects/`», Config и Objects делят судьбу. Разделить S3 и KV — два отказа, два бэкапа. Склеить — один отказ слепит и желание, и факт.

**Курс станет сложнее учить.** Сейчас М11 «вот Nomad, вот Variable, вот CAS». Слой: сначала выдуманный API, потом три бэкенда. Студент позже поймёт k8s, раньше — запутается, где правда. Имеет смысл как *надстройка после* М11, не вместо урока raft.

**Ложное чувство портабельности.** «Готово к k8s» после одного HTTP не значит, что GPU, hostNetwork, device plugin и диск архива переедут. Runtime-провайдер толще Config.

**Согласованность часов и 409.** Свой сервис должен быть **одним** лидером для CAS (raft/etcd). Два инстанса Config без кворума — два 200 на один cas, сломанные эпохи. Нельзя «для простоты» два независимых Config.

## 8. Сравнение с тем, что есть

| | Курс сейчас | Предложение |
|---|---|---|
| Контракт склада | Python `Protocol` | HTTP KV + CAS (и отдельно Objects) |
| Смена М10→М11 | тот же процесс, другой класс | тот же клиент HTTP, другой бэкенд |
| Смена на k8s | новый класс + четыре места в `__main__` (и копия в Go) | новый бэкенд за тем же `CONFIG_URL` + манифесты Runtime |
| Кто знает Nomad? | `__main__` конструирует клиент; воркер читает `NOMAD_*` | слот и токен Config; без имени Nomad в петле |
| Цена на ящике | нулевая (файлы) | демон или два транспорта |
| Цена в зале | агент Nomad уже есть | агент + ваш сервис **или** прокси 1:1 на Nomad (тогда слой тонкий, выигрыш — только стабильный URL) |

Минимальный выигрыш без нового сервиса: клиент в воркере говорит только `CONFIG_URL`; на Nomad `CONFIG_URL` указывает на тот же agent `/v1/var`. Смена k8s — другой URL. Ноль лишних hop. Это уже лучше, чем `NomadVariables()` в `__main__.py`. Полный сервис нужен, когда бэкенд не умеет этот HTTP сам (чистый etcd, Postgres).

## 9. Что делать в курсе, если принять

Не выкидывать Nomad из М11: raft и 409 надо пощупать руками.

Добавить после М11 (или в конце М10) урок-надстройку:

1. Вынести клиент: воркер ходит на `CONFIG_URL`, не на класс.
2. На ящике `CONFIG_URL` = файловый адаптер или localhost.
3. В кластере `CONFIG_URL` = Nomad agent.
4. Упражнение: написать провайдер-память на 30 строк и прогнать тест двух контроллеров.
5. Явно сказать: Runtime — отдельные файлы; failover диска — не в них.

Так результат курса — не «мы навсегда на Nomad», а «мы на контракте; Nomad и k8s — провайдеры плюс политика смерти узла».

## 10. Стоит ли делать

Nomad здесь не потому, что «мир так выбрал». Он уже стоит в системе, и для appliance он технически лучше (см. [`kubernetes-vs-nomad.md`](./М11_ClusterVMS/kubernetes-vs-nomad.md): драйверы, Podman, меньше control plane). Это не повод завязаться на вендоре.

Мир оркестрации — k8s. [CNCF Annual Survey 2025](https://www.cncf.io/announcements/2026/01/20/kubernetes-established-as-the-de-facto-operating-system-for-ai-as-production-use-hits-82-in-2025-cncf-annual-cloud-native-survey/) (опрос опубликован январь 2026): **82%** тех, кто гоняет контейнеры, держат Kubernetes в проде; в 2023 было **66%**. Сопоставимой доли Nomad в тех же опросах нет: это ниша HashiCorp-стека. Плюс Nomad — BUSL / IBM; форка уровня OpenTofu у него нет. Нанимать, интегрировать, сдавать площадку заказчику с «у нас свой оркестратор» через пять лет будет дороже, чем заложить смену сейчас.

Значит слой — не страховка «потом вдруг k8s». Это требование: **продукт не должен знать имя оркестратора**. Иначе смена = правка четырёх `__main__`, Go, М12 и `NOMAD_*` в петле.

**Тонкий клиент `CONFIG_URL` + нейтральный слот — да, сразу.** Это и есть «подразумевать смену»: воркер видит URL и `WORKER_NAME`, не `NomadVariables()` и не `NOMAD_ALLOC_INDEX`. На текущем Nomad URL смотрит в тот же agent. Ноль hop, ноль второго кворума. Так уже сделано для Objects в кластере. Без этого завязка на вендоре остаётся в коде, статистика рынка её не лечит.

**Полный Config-сервис (свой процесс, свой raft) — нет, пока бэкенд — Nomad.** Предполагать смену ≠ поднимать второй raft сегодня. Nomad уже отдаёт нужный HTTP; второй кворум — та цена, за которую курс выкинул Consul. На ящике демон ещё хуже. Свой сервис — когда *бэкенд* уже не Nomad (etcd, чужой KV), не когда вы только решили не прирастать к вендору.

**Манифесты Runtime под k8s — писать не вместо шва, а как второй провайдер.** Слой KV их не заменяет. Шов Runtime закладывать сразу: слот, `CAPACITY`, labels, политика смерти узла (аналоги `lost_after` / `stop_on_client_after` / `kill_timeout`). Сами Deployment/StatefulSet — когда появится площадка на k8s, не «Deployment и готово».

**В курс — надстройкой после М11, не вместо.** Студент должен увидеть raft и 409 на живом Nomad, потом — что клиент говорит `CONFIG_URL`, а Nomad один из бэкендов.

Итого одной строкой:

> Смену оркестратора подразумевать сразу: `CONFIG_URL` и слот без имени вендора. Не строить второй Nomad, пока первый ещё бэкенд. Не обещать, что k8s после этого — три файла. Failover записи от слоя не меняется.

## 11. Что сделано *(16 сентября 2026)*

Принято решение из главы 10: **тонкий шов сейчас, сервиса нет.** Три вещи, ни одного нового процесса.

### 1. Runtime — нейтральные имена

`psimplatform/runtime.py`: `<ROLE>_NAME`, `SLOT_INDEX`, `SERVER_NAME`, `LABELS`, `INSTANCE_ID`. Воркер, шлюз и детектор читают их и больше ничего; мапинг из `NOMAD_ALLOC_INDEX`, `node.unique.name` и `meta.labels` переехал в `env {}` шести jobspec'ов — в файл, который и так знает оркестратор.

Было двенадцать мест в коде с `NOMAD_*`, **половина из них — в `М10_ServerVMS`, модуле про одну коробку, где Nomad нет вообще**. Стало ноль.

### 2. Config — фабрика по URL, не сервис

`psimplatform.variables.open_vars(url)` с реестром схем:

- `file://` — в процессе, как было; на коробке ни демона, ни hop'а, ни второго кворума;
- `nomad://` — регистрирует сам `cluster/variables.py` при импорте, поэтому платформа не называет вендора;
- `k8s://`, `etcd://` — добавляются файлом, а не веткой в платформе.

Это тот же шов, что у Objects (`open_store`) в М11 уже был; Config до него просто не довели. Шестнадцать конструкторов `FileVariables()`/`NomadVariables()` в трёх модулях заменены на `open_vars(CONFIG_URL)`. В М12 federation-строка теперь несёт схему: `CLUSTERS=north=nomad://…|http://minio…`.

`NOMAD_ADDR` остался в двух местах: внутри самого бэкенда Nomad (где ему и место) и умолчанием в точках входа, чтобы существующие задания работали без правки окружения. Точке входа знать оркестратор можно — петле нельзя.

### 3. Сюита соответствия — то, ради чего всё остальное

`tests/test_variables_contract.py`, восемь тестов, пять пунктов контракта:

1. ненаписанный ключ читается как `(None, 0)`;
2. `put` возвращает версию, следующее чтение её отдаёт;
3. CAS — вся история конкуренции: четыре гонщика, один победитель, три отказа;
4. писатель отказан вне своих префиксов — **отказан, а не проигнорирован**;
5. **индекс непрозрачен** — сравнивается на равенство и никогда не упорядочивается.

Пятый пункт тихо решает, возможен ли бэкенд k8s вообще: `resourceVersion` — строка, и арифметика по ней бессмысленна. Пока сюита зелёная, переезд остаётся вопросом восьмидесяти строк.

Сюита параметризуется: `CONTRACT_URL=nomad://… python3 tests/run.py`. Прогнана против **двух** бэкендов — файлового из М10 и `FakeVariables` из М11 (память, свой счётчик, свой ACL): восемь из восьми на обоих, без правки. Новый бэкенд принимается зелёной сюитой, а не на слово.

### Чего не сделано

**Go-порт** (`vmsserver-go`, `clustervms-go`) остался на старых именах: тулчейна Go в этой среде нет, а вносить непроверенные правки в четыре места чтения окружения — хуже, чем оставить явный долг.

**Бэкенд `k8s://`** — когда появится площадка. Отображение из главы 10 записки готово: ключ → ConfigMap, `items` → `data`, `ModifyIndex` → `resourceVersion`, `cas` → 409, `list(prefix)` → label selector, ACL → RBAC и namespace. Единственное, что не ложится напрямую, — **продление слота**: раз в восемь секунд на воркер, на двухстах воркерах двадцать пять записей в секунду, и ConfigMap для этого не предназначен. Под это в k8s есть `Lease` из `coordination.k8s.io`, которым kubelet бьёт heartbeat на тысячах узлов; слот ложится на него один в один.

**Цифры отказа** — по-прежнему не абстрагируются и абстрагироваться не должны: `lease_ttl=30`, `margin=5`, `lost_after=45`, `StopTimeout=20` и их соответствия в k8s (`terminationGracePeriodSeconds`, поведение при `NotReady`). Это чеклист переезда, а не провайдер.

## 12. Коротко

```
сейчас:   воркер ──Python Protocol──► FileVariables | NomadVariables
          процесс ──спека снаружи──► systemd | Nomad

предложение:
          воркер ──HTTP KV+CAS──► Config ──провайдер──► файл | Nomad | etcd
          воркер ──blob────────► Objects──провайдер──► файл | S3
          процесс ──спека──────► Runtime──провайдер──► Quadlet | Nomad | k8s
```

Плюс: воркеры не переписывать под оркестратор; продукт владеет API склада; ящик и зал — смена провайдеров.

Минус: либо лишний сервис и hop, либо всё же два транспорта; failover k8s не бесплатный; легко начать писать второй Nomad; на коробке HTTP может быть лишним.

Не обещать: «простой VMS и кластер отличаются только провайдерами». Отличаются провайдерами **и** тем, есть ли второй диск и как Runtime отличает краш от паузы. Слот и эпоха — не провайдер.
