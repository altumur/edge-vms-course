# grub.cfg — the A/B slot state machine: ORDER / OK / TRY, one attempt per slot

**Role.** Lesson 3, Step 2 (the file header numbers it "Lesson 18, Step 2" in the course-wide numbering). Installed by `bench/build-disk.sh` at `/boot/efi/EFI/BOOT/grub.cfg` on the ESP, written by hand and never regenerated by `update-grub`. GRUB owns slot selection; RAUC only reads and writes the variables through `grub-editenv` (`rauc/system.conf` sets `bootloader=grub`, `grubenv=/boot/efi/grubenv`). The rule: boot the first slot in `ORDER` whose `OK == 1` and `TRY == 0`, and mark it `TRY = 1` as you go. The absence of a later success signal (`rauc status mark-good` from `health/rauc-mark-good.service`, which clears `TRY`) is the failure signal: the next boot skips that slot. The rollback needs no code.

## Stanza by stanza
### Defaults
- `set timeout=3` — three seconds of menu, enough to pick Slot B by hand at the bench.
- `set ORDER="A B"`, `A_OK=0`, `B_OK=0`, `A_TRY=0`, `B_TRY=0` — safe defaults if the environment file is missing or a variable is absent: with both `OK=0` nothing is bootable and the fallback branch picks entry 0.
- `load_env --file=(hd0,gpt1)/grubenv` — reads the variables from the ESP (partition 1 of the first disk). The environment lives outside both slots, "or an update wipes the record of what to boot". `build-disk.sh` and `boot/seed-grubenv.sh` create this file.

### Choose a slot
- `set default=9` — a sentinel meaning "nothing chosen".
- The `for SLOT in $ORDER` loop maps each slot to its menu index (`A` → 0, `B` → 1), copies its `OK`/`TRY` into scratch variables, and sets that slot's `TRY=1` *before* testing it. Then `if OK == 1 and TRY == 0` it sets `default` to that index and breaks. Marking `TRY` first is the one-attempt guarantee: the slot about to be booted is recorded as tried before the kernel runs, so a hang or panic leaves `TRY=1` on disk.

### Nothing bootable
If `default` is still 9, every slot with `OK=1` had `TRY=1` — both attempts spent. The try flags of good slots are cleared (`A_TRY=0`, `B_TRY=0` where `OK=1`) and `default=0` boots slot A: a last resort that gives each good slot another chance rather than stopping at the firmware.

### Persist
- `save_env --file=(hd0,gpt1)/grubenv A_TRY A_OK B_TRY B_OK ORDER` — writes the (possibly updated) try flags back before the menu is shown. This is the write that makes the state machine survive a failed boot.

### Menu entries
- `menuentry "Slot A (OK=$A_OK TRY=$A_TRY)"` — the title prints the state so it can be read off the menu. `search --no-floppy --label rootfs0 --set root` finds the slot by filesystem label, not device order. `linux /vmlinuz root=LABEL=rootfs0 ro console=ttyS0,115200 rauc.slot=A` boots the Debian symlink at the slot root, read-only, on the serial console (`boot.sh` runs `-nographic`), and tells RAUC which slot it is running from (`rauc.slot=` matches `bootname=A` in `system.conf`). `initrd /initrd.img`.
- `menuentry "Slot B …"` — the same with `rootfs1` and `rauc.slot=B`.

## Notes
- The variable names `ORDER`, `A_OK`, `A_TRY`, `B_OK`, `B_TRY` are the ones RAUC's GRUB backend manipulates: `rauc install` sets the target slot's `OK=1 TRY=0` and moves it to the front of `ORDER`; `rauc status mark-good` clears `TRY`; `mark-bad` sets `OK=0`.
- After a successful install of B and a healthy boot, `grub-editenv /boot/efi/grubenv list` shows `ORDER=B A`, `B_TRY=0`. After Lesson 3's broken-kernel bundle it shows `B_TRY=1` and the next boot is A.
- The default set at the top (`A_OK=0`, `B_OK=0`) means a wiped `grubenv` boots slot A through the fallback branch, not through a positive choice; `seed-grubenv.sh` is how you recover a proper state.
